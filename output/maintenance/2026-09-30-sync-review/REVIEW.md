## 이번 수정

- `.gitattributes`: Pi용 `*.sh`, `*.service`를 LF로 고정했다. 현재 파일은 이미 LF였지만 `core.autocrlf=true`만 있는 Windows 새 checkout에서 CRLF로 바뀌어 Pi 실행이 깨질 수 있는 경로를 예방한다. 기존 Git 이력·파일 전체를 일괄 재정규화하지 않았다.
- `.gitignore`: 새 브라우저 프로필·테스트 런타임·node_modules와 이번 격리 데이터를 제외했다.
- `package-for-pi.ps1`: 루트 핫스팟 안내를 허용 목록에 추가했다. 별도 `package-check.tar.gz`로 생성 검증하며 기존 dist를 덮어쓰지 않았다.
- 앱 실행 코드·운영 데이터·Pi 설정은 수정하지 않았다. 커밋·push·reset·이력 재작성도 수행하지 않았다.

## Git 관리 처리 내역과 남은 항목

1. **기존 커밋의 테스트 브라우저 프로필 파일 715개는 후속 사용자 요청으로 작업 폴더에서 삭제 완료했다.** 다음 전체 커밋에 이 삭제를 포함한다. `.gitignore`로 새 프로필의 재유입도 방지한다. 아직 스테이징·커밋하지 않았으므로 현재 인덱스에는 남아 있고 작업 트리에 삭제로 표시된다. 과거 커밋 이력은 재작성하지 않았다.
2. **핫스팟 원문은 시작 시 미추적 파일이었다.** 이번 새 `.gitattributes`와 점검 기록을 포함해 변경 사항은 아직 커밋하지 않았다. 다음 커밋에 원문도 포함해야 다른 환경에서 받을 수 있다.
3. **PC 자체에서 앱을 실행할 루트 `.venv`와 `.env`는 없다.** PC 앱 실행은 기존 안내대로 `setup.ps1` → 필요한 키 설정 → `start.ps1` 순서다. `start.ps1`만 실행하면 가상환경 부재 오류가 정상적으로 발생한다. Pi를 보는 시연 노트북에는 이 설치가 필요 없다.
4. `dist/`, `data/`, `.env`, 가상환경은 의도적으로 Git에서 제외된다. 새 clone에서는 배포 패키지를 생성하거나 PC 환경을 설치해야 하며 Pi의 기존 데이터·키가 Git에서 복원되는 것은 아니다.
5. 대량 커밋 날짜는 여러 날의 개발을 한 번에 반영한 시점이다. 기능별 실제 개발일·팀 기여율을 이 한 커밋만으로 산정하지 않는다.

다음 시연 작업은 최신 핫스팟 가이드 8절의 전원 재인가·자동 연결 시험이다. 이번 로컬 점검을 그 시험의 완료 기록으로 바꾸지 않는다.
