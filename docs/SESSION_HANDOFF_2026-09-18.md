### 0-1. 9월 22일 완료 — 개발 중간보고 PPT

**시작 문서·PC 환경 후속 정리:** `START_HERE.md`는 수정 전 종료 기록의 해시와 일치했으며 프로젝트 소개·PPT 보완 순서·PC 실행 안내를 보강했다. 사용자가 PC 프로젝트의 `.venv`를 직접 삭제했고 현재 부재를 확인했다. 다음 PC 앱 실행은 Python 3.11 이상과 패키지 다운로드 연결을 준비한 뒤 루트에서 `setup.ps1` → `start.ps1` 순서다. `start.ps1`만으로는 환경이 재생성되지 않는다. PPT·문서 검토를 위해 환경을 미리 만들 필요는 없다. 아래 `.venv` 보존 기록은 사용자 삭제 이전 정리 시점의 기록이며 Pi 설치 상태와는 별개다. 이번 후속 작업에서 설치·앱 실행·앱 테스트를 수행하지 않았다.

**세션 종료:** 사용자가 PPT 초안을 “일단 좋아”라고 우선 수용한 뒤 오늘 작업 종료와 다음 LLM 인계·캐시 정리를 요청했다. 현재 PPT 내용의 새 수정 요청은 없으며, 캡처·공식 진행률·정량 결과가 빈 상태임을 유지한다. 다음에는 기존 PPT를 함께 검토하거나 캡처부터 채운다. 최초 목적·분량 질문과 설치를 다시 시작하지 않는다. 명시적인 선택 없이 논문 계측 개발로 넘어가지 않는다.

## 4. 시연 준비를 이어갈 때

현재 절차의 원문은 [Windows 핫스팟 가이드](../REFOUND_WINDOWS_HOTSPOT_GUIDE.md)다. **Pi 설치·Wi-Fi 프로필 생성·키 입력을 반복하지 않는다. 노트북은 Pi 화면을 여는 역할이므로 앱 설치도 필요 없다.**

1. 노트북을 학교 인터넷 Wi-Fi에 연결하고 `ReFoundLaptop` 핫스팟을 켠 뒤 Pi 전원을 연결해 약 2~3분 기다린다. 집에서는 인터넷이 되는 집 Wi-Fi를 사용한다. 9월 29일 실제 상위 Wi-Fi 이름은 미확인이다.
2. Pi가 나타나면 **Windows 새 PowerShell**에서 `ssh -o ExitOnForwardFailure=yes -L 18000:127.0.0.1:8000 refound@refound-pi.local`을 실행한다. Pi 로그인 비밀번호로 로그인하고 창을 유지한다. Pi 내부에서 터널을 시작하지 않는다.
3. 같은 노트북에서 `http://127.0.0.1:18000`을 연다. 이름을 찾지 못하면 Windows 핫스팟 장치 목록의 현재 Pi IP로 `@` 뒤만 바꾼다.
4. 첫 재실행 때 최종 Wi-Fi 프로필의 자동 연결·우선순위 설정 결과와 서비스 enabled 여부를 확인한다. 수정 명령은 백업 6절에 안내됐지만 실제 실행 결과는 받지 않았다. 이름·UUID가 없으면 목록부터 확인한다.
5. 진행 중인 처리가 끝나면 Pi에서 `sudo shutdown -h now`를 실행한다. 초록 ACT LED의 종료 점멸이 끝난 뒤 전원을 분리한다. 무선 단독 시험은 정상 종료 후 랜선을 분리하고, 기존 `s24+`는 끈 상태에서 노트북 핫스팟을 먼저 켜고 전원을 다시 연결한다.
6. 핫스팟 자동 연결 → Windows에서 SSH 터널 재실행 → 실제 영상·실물 AI 복귀를 확인하고 [실기 확인표](guides/PI_ACCEPTANCE_CHECKLIST.md)에 결과를 추가한다. 이번 기록에는 아직 이 시험 결과가 없다. 편집·기한·메일·privacy·다중 물품·장시간 안정성은 별도 남은 항목이다.

종료는 Pi 정상 종료·전원 분리 후 노트북 핫스팟을 끄는 순서다. 터널이 끊긴 것만으로 전원 분리 가능하다고 판단하지 않는다. 기존 Tailscale Serve와 loopback 앱 설정은 유지하며 친구 수락 여부는 별도 경로로 확인한다. Android/Tailscale 대안은 [학교 시연 가이드](guides/SCHOOL_DEMO_GUIDE.md)에 보존한다. 이 방식으로 돌아갈 때만 초대·계정 확인을 이어간다.
