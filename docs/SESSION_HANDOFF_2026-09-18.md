## 0. 후속 완료 — 개발 중간보고 PPT

**시작 문서·PC 환경 후속 정리:** `START_HERE.md`는 수정 전 종료 기록의 해시와 일치했으며 프로젝트 소개·PPT 보완 순서·PC 실행 안내를 보강했다. 사용자가 PC 프로젝트의 `.venv`를 직접 삭제했고 현재 부재를 확인했다. 다음 PC 앱 실행은 Python 3.11 이상과 패키지 다운로드 연결을 준비한 뒤 루트에서 `setup.ps1` → `start.ps1` 순서다. `start.ps1`만으로는 환경이 재생성되지 않는다. PPT·문서 검토를 위해 환경을 미리 만들 필요는 없다. 아래 `.venv` 보존 기록은 사용자 삭제 이전 정리 시점의 기록이며 Pi 설치 상태와는 별개다. 이번 후속 작업에서 설치·앱 실행·앱 테스트를 수행하지 않았다.

**세션 종료:** 사용자가 PPT 초안을 “일단 좋아”라고 우선 수용한 뒤 오늘 작업 종료와 다음 LLM 인계·캐시 정리를 요청했다. 현재 PPT 내용의 새 수정 요청은 없으며, 캡처·공식 진행률·정량 결과가 빈 상태임을 유지한다. 다음에는 기존 PPT를 함께 검토하거나 캡처부터 채운다. 최초 목적·분량 질문과 설치를 다시 시작하지 않는다. 명시적인 선택 없이 논문 계측 개발로 넘어가지 않는다.

사용자가 첨부 목차에 맞춘 발표 PPT를 요청해 **[30장 PPTX](../output/presentation/REFOUND_PROJECT_MIDTERM_2026-09-22_v3.pptx)**와 **[캡처·결과표 작성 가이드](../output/presentation/REFOUND_MIDTERM_FILL_GUIDE.md)**를 제작했다. 본문 27장과 보충자료 3장, 16:9이며 표·구성도·코드·그래프는 편집 가능하다. 분량은 사용자가 맡겼고 교수님·수강생과 약 15–20분을 제작상의 출발점으로 가정했다.

수업 일정은 **9/22 중간보고 작성 시작, 9/29 작성, 10/13 중간보고 발표, 10/27 최종보고 연습, 11/03 최종보고 발표**다. 이후 11/10 본론, 11/17 팀논문, 11/24 최종논문 발표가 있다. PPT의 사실 기준은 9/22이며 미래의 개발 일정은 제안 계획이다.

## 1. Pi에서 멈춘 곳과 다음 선택

사용자는 친구에게 **새 Pi의 Tailscale 장치 공유 초대 링크를 전송**했고 응답을 기다리며 작업을 중단했다. 친구의 수락·시연 노트북 접속·친구 안드로이드 핫스팟 시험은 아직 미확인이다. Pi에서 `sudo shutdown -h now`로 정상 종료하도록 안내했지만 실제 종료·전원 분리 완료 보고는 받지 않았다.

다음 요청은 **기존 발표 PPT 보완** 또는 **시연 준비 계속**으로 이어갈 수 있다. 발표 작업에 친구 응답이나 나머지 실기 점검을 선행 조건으로 강제하지 않는다. 발표 목적·분량 위임·수업 일정은 0절의 후속 작업에서 정했다. 정확한 제한 시간은 정해지지 않았으며 15–20분은 제작 가정이다.

## 4. 시연 준비를 이어갈 때

계획은 **집 공유기 LAN + 본인 PC로 설치 → 본인 소유 Pi를 친구 Tailscale 계정에 장치 공유 → 시연은 친구 노트북과 친구 안드로이드 핫스팟**이다. 친구에게 본인 계정 비밀번호를 넘길 필요가 없다. 장치 공유를 수락한 친구도 앱의 편집·초기화 기능을 사용할 수 있다.

1. Pi가 꺼져 있다면 전원을 켠다. 설치·API 키 입력·Tailscale 설치를 반복하지 않는다.
2. 친구의 초대 수락 여부를 확인한다. 친구는 **실제 시연 노트북 Tailscale에 로그인한 것과 같은 계정**으로 링크를 수락한다. `Reusable link`는 초대 링크 재사용 옵션이며, 꺼도 첫 수락 뒤 공유는 유지된다. 링크를 이미 보냈으므로 필요 없이 다시 만들지 않는다.
3. 친구 노트북의 Tailscale을 연결하고 위 **전체 HTTPS 주소**로 화면·영상을 확인한다. 집에 있는 Pi는 이 단계까지 랜선을 유지해도 된다.
4. 친구 핫스팟의 실제 SSID·보안 방식·저장된 Pi Wi-Fi와의 일치를 확인한다. 폰은 갤럭시 또는 다른 안드로이드이고 정확한 기종·SSID·최종 보안 방식은 아직 미확인이다. 비밀번호는 채팅이나 문서에 요청·기록하지 않는다.
5. 친구 핫스팟을 켜고 **정상 종료한 Pi의 랜선을 뺀 뒤 부팅**하여 자동 연결을 확인한다. 친구 노트북에서 영상·등록·회수·시연 초기화를 확인한다. 현장 구성 검증은 이 단계가 끝나야 한다.
6. 필요하면 남은 편집·기한·메일·privacy·다중 물품 점검을 [실기 확인표](guides/PI_ACCEPTANCE_CHECKLIST.md)에 추가한다.

사용자는 시연 때만 비밀번호 없는 핫스팟을 고려했다. 안드로이드가 보안 없음/None을 지원하면 공개 네트워크로 저장할 수 있다는 안내를 했고 비밀번호 사용을 권장했다. 최종 설정을 추측하지 않는다. 상세 순서는 [학교 시연 가이드](guides/SCHOOL_DEMO_GUIDE.md)를 따른다.

Tailscale Serve는 설정됐고 Funnel은 비활성이다. Pi 앱은 loopback을 유지한다. HTTPS 접속에는 SSH 터널이 필요 없다. 진단은 Pi의 `bash /opt/refound/scripts/raspberry-pi/check-system.sh`, 종료는 `sudo shutdown -h now`다.

시연 초기화는 **모든 출처의 물품·활동·알림·캡처**를 백업 없이 삭제하며 설정·키·기존 백업은 유지한다. API 기본값은 기존 백업 초기화이고 `mode=quick`은 명시적으로만 실행한다. 카메라·알림 worker 종료, 잠금, 삭제 경로 검사를 공유하고 작업을 안전하게 멈추지 못하면 409로 취소한다. 삭제 자동 재시도는 없다. 초기화 전에 물건을 치워 빈 장면을 기준으로 잡아야 한다.
