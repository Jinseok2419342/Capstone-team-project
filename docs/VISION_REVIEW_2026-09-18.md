# 정지 영상 안정성과 Pi 연산 부담 개선 — 2026-09-18

사용자는 Raspberry Pi의 CSI 카메라와 PC USB 웹캠 양쪽에서 가만히 있는 영상이 미세하게 움직이거나 밝기가 변하는 현상을 본 것 같다고 설명했다. 실제 장치에는 접근하지 않고 코드·합성 입력·독립 회귀 검사로 재현 가능한 부분을 수정했다.

## 확인한 원인

1. 감지용 기하 정합 결과를 미리보기 영상으로도 보냈다. 1280×720 정지 합성 장면의 저대비 잡음만으로 약 1.4px, 국소 밝기 변화로 약 1.75px의 잘못된 정합 이동이 발생했다. 물품 사건이 0건이어도 화면은 움직일 수 있었다.
2. 분석한 시각으로 매번 FPS 제한 기준을 갱신하여 10fps 입력에서 7fps 설정이 5fps로 낮아졌다.
3. 매 프레임 변하지 않는 기준 영상의 grayscale을 다시 계산하고, 변화가 없는 경우에도 Sobel·형태 연산·contour를 모두 계산했다.
4. 이미 기준 좌표에 정합한 안정 장면을 detector core에서 다시 정합했다. Lab 두 채널 차분도 비연속 배열 복사와 NumPy reduction에 불필요한 시간이 들었다.
5. 카메라의 실제 노출·게인·초점 변화와 소프트웨어 정합을 구분할 진단 정보가 없었다. 실제 장비 모델과 자동 제어 상태는 이번 작업에서 확인되지 않았다.

## 구현 변경

- 미리보기는 카메라 원래 좌표를 사용한다. 감지 좌표의 물품 박스만 역변환·축소해서 표시하며 영상 자체에 분석용 affine 보정을 적용하지 않는다.
- 분석·미리보기 각각 deadline 기반으로 주기를 제어한다. 정지·지연 이후 과거 프레임을 몰아서 처리하지 않는다.
- Pi 기본 미리보기는 **800×450, 5fps**다. 기본 촬영·분석은 **1280×720**, 후보 증거 JPEG 품질은 **88**이다. 다른 화면 비율이면 미리보기 높이를 비율에 맞춘다.
- 기준 grayscale을 캐시하고 기준 갱신·재연결·privacy·재설정 시 갱신한다.
- 보정 차분의 최대값이 움직임 임계값 이하이면 결과가 확실히 빈 마스크이므로 후처리를 생략한다. 실제 변화가 있으면 기존 경계 억제와 판정을 수행한다.
- 중복 정합을 생략하고 Lab 차분을 연속 배열의 OpenCV 채널 연산으로 대체한다. 미리보기 상태 패널은 해당 영역만 합성한다.
- 실제 처리 FPS, 최근 프레임 처리 시간, 미리보기 크기를 카메라 화면에 표시한다. 처리 시간은 해당 프레임의 연산 시간이며 물품 사건의 종단간 지연이 아니다.
- 지원되는 Picamera2 장치에서 같은 프레임에 속한 노출·게인·렌즈 위치 등만 읽는다. 별도 프레임 캡처를 추가하지 않는다. 재연결 시 이전 센서 정보는 지운다.
- 설정에 조명 보정 `기본값 유지 / 50Hz / 60Hz`를 추가했다. 지원되는 CSI 제어에만 적용하며 미지원·실패 시 영상은 유지하고 적용 불가를 알린다. 기본값은 0이며 AE·AWB·자동 초점을 강제로 잠그지 않는다.

## 개발 벤치마크

측정 원장은 `output/maintenance/2026-09-18-vision-review/benchmark-before.json`, `benchmark-current.json`, `benchmark-comparison.json`이다. 원장에 실행 환경·소스 SHA256·프로파일과 수치를 보존했다.

Windows x64, OpenCV 1스레드, OpenCL 비활성, 1280×720 합성 입력을 사용한다. 실제 `_run` 루프에 가상 촬영 시계를 주입해 **연산 시간**과 프레임 선택을 확인한다. 카메라 대기·DB·콜백 소비·브라우저·외부 AI·열·전력은 포함하지 않는다. 추적 중인 물품은 0개다. 전후 검사는 별도 프로세스에서 순차 실행했다.

정지 및 잡음 장면 모두 가상 16초의 160개 촬영 프레임에서 분석은 **80→112개**, 미리보기는 **80개**였다. 이는 스케줄러가 7fps 분석 목표를 유지한다는 검증이며 실제 Pi가 7fps를 달성했다는 결과가 아니다. 전후 합성 정지 사건은 0건이었다. 비교한 물품 추가 pair에서는 사건 종류·bbox·confidence와 증거 JPEG 4개의 SHA256이 일치했다.

정확한 시간 수치와 실행 환경은 위 JSON을 따른다. 데스크톱 벤치마크를 논문용 Pi 성능값·현장 정확도로 옮기지 않는다.

최종 소스에서 정지 장면은 **27.76→13.21ms/분석 프레임**이었다. 앞선 반복도 대략 26~28→13~14ms였지만, 다른 사례에는 호스트 부하에 따른 큰 시간 변동이 있었다. 변동이 큰 실행을 포함해 이전 기록을 보존했고 비교 JSON에 한계를 명시했다. 정확한 Pi 개선율이나 처리 FPS 보장이 아니다.

```powershell
python scripts/benchmarks/vision_pipeline.py --threads 1 --frames 160 --output output/vision-current.json
python scripts/benchmarks/vision_pipeline.py --threads 1 --frames 160 --source-zip output/maintenance/2026-09-18-vision-review/source-before.zip --output output/vision-before.json
```

시간을 비교할 때 두 명령을 순차 실행하고 다른 벤치마크·테스트와 동시에 실행하지 않는다.

## 검증 및 남은 확인

- 전체 Python **202개**, Node **13개** 통과. Python 컴파일·JavaScript 문법·HTML ID/ARIA 검사 통과.
- 현재 데스크톱 OpenCV 5.0 외에 임시 디렉터리의 OpenCV **4.11.0**으로 영상·카메라 테스트 **74개**를 별도 실행해 모두 통과했다. 기존 환경은 변경하지 않았으며 이 호환 검사는 실제 Pi 하드웨어 검사가 아니다.
- 정지 잡음·조명, 작은 물품·얇은 물품·누적 이동, 원본 미리보기 픽셀, 역변환 박스, 증거 해상도, 10→7fps 주기, 캐시 재설정, grayscale/BGRA, 센서 미지원·실패를 회귀 검사했다.
- 국소 밝기 보정을 움직임 감지에 무조건 켜면 실제 큰 저대비 물품이 사라지는 재현 사례가 있어 기본 동작을 유지했다. 국소 조명 변화가 잠시 안정화 대기를 유발할 수 있다.
- 원본 카메라에서 발생한 물리적 흔들림·밝기 변화 자체는 미리보기 경로 분리로 제거되지 않는다. 실제 Pi/USB 영상과 브라우저 시각 검사는 아직 수행하지 않았다.
- 새 버전에서 카메라 화면의 처리 FPS/시간을 확인하고, 밝기가 계속 달라지면 CSI의 센서 진단에서 노출·게인이 함께 변하는지 확인한다. 조명 전원 주파수를 알고 있고 드라이버가 지원할 때 50/60Hz를 선택한다. 초점 원인은 렌즈 정보·실제 모델을 확인한 뒤 판단한다.
- 기존 운영 데이터·실제 촬영 파일·논문 결과값은 변경하지 않았다. 논문 원고의 스트림 처리·미리보기·성능 설정 설명은 본 구현 기준과 다시 대조해야 한다.

센서 API와 제어 의미는 [Picamera2 공식 설명서](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf) 및 [libcamera 공식 제어 정의](https://raw.githubusercontent.com/raspberrypi/libcamera/main/src/libcamera/control_ids_core.yaml)를 확인했다. 센서 모드와 제공되는 제어는 장치·드라이버에 따라 다르므로 코드에서 지원 범위를 확인한다.
