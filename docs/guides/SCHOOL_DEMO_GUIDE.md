# Re:Found 학교 시연 운영 가이드

이 문서는 **새 SD에 설치와 기본 실물 동작 확인을 마친 뒤** 학교에서 운영하는 방법입니다. 현재 작업을 이어갈 때는 [실기 결과](PI_ACCEPTANCE_CHECKLIST.md)를 먼저 보고, 새 카드를 처음부터 만드는 경우에만 [새 SD 설치 절차](FRESH_SD_START.md)를 따릅니다.

**2026-09-22 최신 계획:** 집 공유기와 Pi를 랜선으로 연결해 사용자 PC로 설치 → Pi를 사용자 본인 Tailscale에 등록 → 시연 담당 친구 계정에 Pi 한 대 공유 → 시연 때 Pi는 친구 안드로이드 핫스팟, 발표는 친구 노트북에서 진행합니다. 아래 `ReFoundPhone`은 실제 친구 핫스팟 이름으로 바꿉니다. 친구 공유 수락·무선 자동 연결·이 현장 구성에서의 시연은 아직 미검증입니다.

**2026-09-22 현재:** 새 SD 설치·카메라 검사·기본 실물 등록/이동/회수·재부팅 진단과 본인 PC Tailscale 화면·영상 확인을 마쳤습니다. 친구에게 새 Pi 장치 공유 초대 링크를 보냈고 응답을 기다립니다. 친구 계정의 접속과 핫스팟 부팅 시험은 아직 남았습니다. 현재 주소와 증거는 [작업 인계](../SESSION_HANDOFF_2026-09-18.md), 항목별 결과는 [실기 확인표](PI_ACCEPTANCE_CHECKLIST.md)를 따릅니다.

이전 카드에서 확인했던 과거 상태는 다음과 같습니다. 이 목록만으로 새 카드의 미확인 항목까지 성공으로 취급하지 않습니다.

- Raspberry Pi 4와 카메라가 정상 작동합니다.
- `refound.service`가 부팅할 때 자동으로 시작합니다.
- Tailscale Serve가 설정되어 있습니다.
- 당시 관리자 주소로 원격 접속을 확인했습니다. 새 주소는 새 Pi의 `sudo tailscale serve status` 출력에서 다시 확인합니다.
- 실제 파란색 볼펜의 등록과 자동 회수를 확인했습니다.
- 당시에는 OpenAI API 키만 설정되어 있었습니다.

> 아래 `refound-pi.YOUR-TAILNET.ts.net`은 예시입니다. **새 Pi의 실제 전체 주소로 바꿉니다.** 장치명에 `-1` 같은 접미사가 붙을 수 있습니다. Tailscale Funnel과 공유기 포트포워딩은 켜지 않습니다.

다른 새 SD를 처음 설치할 때는 Tailscale 설치·로그인·Serve 설정이 필요합니다. **현재 새 카드에서는 이 설정을 완료했으므로** 매번 `setup-tailscale.sh`를 실행하지 않습니다. 현재 설정은 OpenAI이며 제공자 전환은 발표 직전이 아닌 여유 있는 날 별도로 시험합니다.

## 전체 구성

학교에서는 학교 Wi-Fi에 Raspberry Pi를 직접 연결하지 않습니다.

```text
Raspberry Pi ──Wi-Fi──> 친구 Android 핫스팟 ──인터넷──> Tailscale (사용자 소유 Pi)
친구 노트북 ──학교 Wi-Fi 또는 같은 Android 핫스팟─────> Tailscale (친구 계정, Pi 공유 수락)
                                                    │
                                                    └─> Re:Found 관리자 웹
```

Pi와 노트북이 같은 Wi-Fi일 필요는 없습니다. 양쪽에 인터넷이 있고 **친구 노트북에서 로그인한 계정으로 Pi 공유 초대를 수락**했으며 접근 정책이 연결을 허용해야 합니다. 같은 tailnet의 허용된 구성원도 접속할 수 있습니다. 처음 시연에서는 노트북도 친구 핫스팟에 연결하는 구성을 권장합니다. 휴대전화는 인터넷을 공급하므로 Tailscale 앱이 필요하지 않습니다. [공식 장치 공유](https://tailscale.com/docs/features/sharing)

## 1. 집에서 한 번만 할 설정

### 1-1. Android 핫스팟을 고정된 값으로 설정

휴대전화에서 다음 메뉴를 엽니다. 제조사와 Android 버전에 따라 이름이 조금 다릅니다.

- 삼성 Galaxy: **설정 → 연결 → 모바일 핫스팟 및 테더링 → 모바일 핫스팟**
- Pixel·기타 Android: **설정 → 네트워크 및 인터넷 → 핫스팟 및 테더링 → Wi-Fi 핫스팟**

다음처럼 설정합니다.

| 항목 | 권장값 |
|---|---|
| 네트워크 이름 | `ReFoundPhone` |
| 비밀번호 | 영문·숫자를 섞은 12자 이상의 새 비밀번호 |
| 보안 | WPA2 또는 WPA2/WPA3 |
| 주파수·대역 | **2.4GHz** 또는 호환성 모드 |
| 숨겨진 네트워크 | 끔 |
| 연결된 기기가 없을 때 자동 종료 | 끔 또는 제한 없음 |
| 최대 연결 기기 | 2대 이상 |

비밀번호는 이 문서나 발표 자료에 적지 말고 비밀번호 관리자에 보관합니다. 이후 SSID나 비밀번호를 바꾸면 Pi에도 다시 저장해야 합니다.

사용자는 시연 시간에만 **비밀번호 없는 핫스팟**을 쓰는 방안도 제안했습니다. 친구 안드로이드에서 보안 `없음/None`을 제공한다면 가능합니다. 이 경우 Imager의 Wi-Fi를 **공개 네트워크**로 선택하고 같은 SSID를 입력합니다. 비밀번호를 써도 한 번 저장한 Pi는 자동 연결하며, 공개 핫스팟에는 주변 사람도 연결할 수 있어 위 표는 비밀번호 사용을 권장값으로 유지합니다. 실제 보안 방식은 친구와 확정한 후 Pi 설정과 맞춥니다. [Android 공식 안내](https://support.google.com/android/answer/9059108?hl=en)

이제 휴대전화의 다음 항목을 확인합니다.

1. 모바일 데이터를 켭니다.
2. 핫스팟을 켭니다.
3. 배터리 절약 모드와 데이터 절약 모드를 잠시 끕니다.
4. 가능하면 휴대전화를 충전기에 연결합니다.

### 1-2. 핫스팟 정보를 Raspberry Pi에 저장

Imager에 친구 핫스팟을 이미 저장했다면 이 절에서 새로 입력할 필요 없이 **1-3의 랜선 없는 부팅 시험**으로 확인합니다. 아직 모르는 SSID·비밀번호는 집의 유선 설치 후 이 절에서 추가할 수 있으며 SD를 다시 쓸 필요가 없습니다.

먼저 기존 방식으로 Pi에 SSH 접속합니다. 아래 명령은 **Raspberry Pi SSH 터미널**에서 한 줄씩 실행합니다.

```bash
nmcli dev wifi rescan
nmcli dev wifi list
```

목록에 `ReFoundPhone`이 보여야 합니다. 보이지 않으면 Android에서 핫스팟이 켜졌는지, 주파수가 2.4GHz인지 확인하고 다시 실행합니다.

다음 명령을 실행합니다.

```bash
sudo nmcli --ask dev wifi connect "ReFoundPhone"
```

`Password:`가 나오면 Android 핫스팟 비밀번호를 입력합니다. 입력 중 글자나 별표가 보이지 않아도 정상입니다.

> 이 명령이 성공하면 Pi가 기존 Wi-Fi에서 휴대전화로 이동하므로 **현재 SSH 창이 끊길 수 있습니다. 정상 동작입니다.**

SSH가 끊겼다면 다음 순서로 다시 연결합니다.

1. Windows 노트북도 잠시 `ReFoundPhone` Wi-Fi에 연결합니다.
2. 20~30초 기다립니다.
3. Windows PowerShell을 새로 엽니다.
4. 다음 명령을 실행합니다.

```powershell
ssh refound@refound-pi.local
```

`.local` 주소를 찾지 못하고 Windows Tailscale이 연결돼 있다면 Tailscale 이름으로 시도합니다.

```powershell
ssh refound@refound-pi.YOUR-TAILNET.ts.net
```

그것도 안 되면 Android의 **연결된 기기** 목록에서 `refound-pi`의 IP 주소를 보고 다음처럼 접속합니다.

```powershell
ssh refound@192.168.43.27
```

다시 접속한 Pi 터미널에서 저장된 연결 이름을 확인합니다.

```bash
nmcli -f NAME,TYPE,AUTOCONNECT connection show
```

Wi-Fi 연결 이름이 `ReFoundPhone`이면 다음을 실행합니다. 이름이 다르게 표시되면 따옴표 안을 실제 `NAME` 값으로 바꿉니다.

```bash
sudo nmcli connection modify "ReFoundPhone" connection.autoconnect yes connection.autoconnect-priority 50
```

### 1-3. 전원만 연결해도 살아나는지 시험

집에서 랜선으로 설치했다면 아래 재부팅 시험에서는 **Pi가 종료된 뒤 랜선을 분리**합니다. 유선 인터넷이 남은 상태로는 친구 핫스팟만으로 접속되는지 검증할 수 없습니다.

Android 핫스팟을 계속 켜 둔 상태에서 Pi를 안전하게 종료합니다.

```bash
sudo shutdown -h now
```

SSH가 끊긴 뒤 30초 정도 기다리고, Pi의 초록색 ACT LED가 깜박이지 않을 때 전원 플러그를 뽑습니다. 다음 순서로 실제 학교 상황을 재현합니다.

1. Android 모바일 데이터와 `ReFoundPhone` 핫스팟을 먼저 켭니다.
2. Pi 전원을 연결합니다.
3. 2~3분 기다립니다.
4. Android의 **연결된 기기**에 `refound-pi`가 보이는지 확인합니다.
5. 노트북에서 Tailscale 상태가 `Connected`인지 확인합니다.
6. 브라우저에서 `https://refound-pi.YOUR-TAILNET.ts.net/`을 엽니다.

웹이 열리면 다음 항목을 확인합니다.

- 카메라 페이지에 실제 라이브 영상이 나옵니다.
- AI 분석 시스템에 `OpenAI · 모델명`과 `키 설정됨`이 표시됩니다. 키의 유효성과 실제 분석 성공은 아래 실물 시험에서 확인합니다.
- 감지 상태가 잠시 후 **변화를 기다리는 중**으로 바뀝니다.
- 물건 하나를 놓았을 때 등록되고, 완전히 치웠을 때 회수됩니다.

이 냉간 부팅 시험을 한 번 통과해야 학교에서 모니터와 키보드 없이 Pi를 켤 수 있습니다.

### 1-4. 서로 다른 네트워크도 시험

마지막으로 다음 상태를 일부러 만듭니다.

- Pi: Android `ReFoundPhone`에 연결
- 노트북: 집 Wi-Fi에 연결
- 노트북 Tailscale: `Connected`

같은 관리자 주소가 열리고 라이브뷰가 갱신되면, 학교에서도 Pi와 노트북이 같은 Wi-Fi일 필요가 없습니다.

### 1-5. 친구의 Tailscale 계정에 Pi 공유

1. 실제 시연 노트북에 Tailscale을 설치하고 친구 계정으로 로그인합니다.
2. 사용자의 Tailscale 관리 화면 **Machines → 새 Pi → Share**에서 해당 Pi의 공유 링크를 만듭니다. 공유할 대상은 시연 담당 친구 한 명입니다.
3. 친구가 **노트북에 로그인한 것과 같은 계정**으로 링크를 열고 공유를 수락합니다. 다른 계정으로 수락하면 노트북에서 공유 장치가 보이지 않을 수 있습니다.
4. 친구 노트북에서 새 Pi의 `tailscale serve status`에 나온 **전체 `https://…ts.net` 주소**를 엽니다. 공유 장치에는 짧은 `refound-pi` 이름 대신 전체 주소를 사용합니다.
5. 친구 휴대전화 핫스팟으로 Pi를 부팅하고, 친구 노트북에서 영상·실물 등록·시연 초기화·재접속을 확인합니다. 접근이 막히면 소유자·친구 측 접근 정책과 HTTPS 443 허용 여부를 확인합니다.

이 방식은 친구를 사용자 tailnet 전체의 구성원으로 초대하는 것과 다릅니다. 친구가 공유받는 것은 Pi 한 대이며, **Re:Found 내부에는 읽기 전용 역할이 없어 친구도 편집·초기화 등 관리 기능을 사용할 수 있습니다.** Serve가 공유받은 사용자의 접속을 지원하므로 Funnel이나 앱 LAN 공개는 필요하지 않습니다. [공식 공유 절차](https://tailscale.com/docs/features/sharing), [공유받은 사용자의 Serve 접속](https://tailscale.com/docs/features/tailscale-serve#identity-headers)

## 2. 발표 전날 점검

아래 순서대로 한 번만 완주합니다.

- [ ] Android 핫스팟 이름과 비밀번호를 설정할 때와 동일하게 유지했습니다.
- [ ] 핫스팟 2.4GHz·자동 종료 끔을 확인했습니다.
- [ ] Pi를 전원만 연결해 부팅했고 Android의 연결 기기에서 확인했습니다.
- [ ] 노트북 Tailscale이 로그인된 상태입니다.
- [ ] 친구 노트북의 계정으로 새 Pi 공유를 수락하고, 랜선 없이 친구 핫스팟만으로 접속했습니다.
- [ ] `https://refound-pi.YOUR-TAILNET.ts.net/`이 열립니다.
- [ ] 라이브뷰가 정상이고 화면이 잘리지 않습니다.
- [ ] 파란색 볼펜처럼 이미 성공한 물건으로 등록 3회, 회수 3회를 시험했습니다.
- [ ] API 분석 결과의 이름과 보관 기간을 확인했습니다.
- [ ] 카메라와 거치대를 건드리지 않아도 화면이 안정적입니다.
- [ ] Pi 전원 어댑터, Android 충전기, 노트북 충전기를 챙겼습니다.
- [ ] 발표용 물건과 배경이 서로 잘 구분됩니다.

테스트가 끝나면 다음 명령으로 안전하게 종료합니다.

```bash
sudo shutdown -h now
```

## 3. 학교 도착 후 실제 준비 순서

### 3-1. 전원 연결 전

1. 촬영대를 먼저 놓고 카메라를 단단히 고정합니다.
2. 렌즈가 분실물 보관 영역만 찍도록 합니다.
3. 사람 얼굴, 모니터, 문서와 출입구가 촬영되지 않게 구도를 잡습니다.
4. Android를 충전기에 연결합니다.
5. Android에서 모바일 데이터를 켭니다.
6. `ReFoundPhone` 핫스팟을 켭니다.
7. 핫스팟 자동 종료와 절전 모드가 꺼졌는지 다시 확인합니다.

### 3-2. Pi 부팅과 네트워크 확인

1. Pi 전원을 연결합니다.
2. **아무것도 누르지 말고 2~3분 기다립니다.**
3. Android의 핫스팟 **연결된 기기**에 `refound-pi`가 나타나는지 확인합니다.
4. 처음 시연에서는 노트북도 `ReFoundPhone`에 연결합니다. 전날 서로 다른 네트워크 시험을 통과했다면 학교 Wi-Fi를 사용해도 됩니다.
5. Windows 작업 표시줄에서 Tailscale이 `Connected`인지 확인합니다.
6. 브라우저에서 `https://refound-pi.YOUR-TAILNET.ts.net/`을 엽니다.

학교 Wi-Fi에서 주소가 열리지 않으면 노트북도 `ReFoundPhone`에 연결하고 다시 엽니다. 이 변경만으로 해결되면 학교망이 Tailscale 또는 VPN 통신을 제한한 것입니다.

### 3-3. 카메라와 기준 화면 준비

1. 관리자 웹의 **카메라** 메뉴를 엽니다.
2. 영상이 실제 촬영대를 모두 보여 주는지 확인합니다.
3. 카메라를 고정한 뒤 자동 노출과 초점이 안정되도록 15초 정도 기다립니다.
4. 감시 구역에서 물건을 모두 치웁니다.
5. **기준 화면 재설정**을 누릅니다.
6. 손과 몸을 화면 밖으로 빼고 기다립니다.
7. 상태가 **변화를 기다리는 중**이 되면 준비 완료입니다.

카메라 위치, 각도, 줌, 조명 또는 촬영대를 바꿨다면 기준 화면도 다시 잡아야 합니다.

### 3-4. 발표용 데이터 초기화

깨끗한 발표 화면이 필요할 때만 실행합니다.

1. 실제 촬영 구역의 물건을 **먼저 모두 치웁니다**.
2. 화면이 안정될 때까지 기다립니다.
3. 메인 대시보드에서 **시연 초기화**를 누릅니다.
4. **백업 없이 초기화**를 한 번 눌러 실행합니다. 모든 물품·활동·알림·사진이 삭제되고 기준 화면을 다시 잡습니다.
5. **변화를 기다리는 중**을 확인하고 다음 물품을 놓습니다.

시연 초기화는 되돌릴 수 없으며 설정·API 키는 유지합니다. 백업이 필요할 때는 **설정 → 시스템 → 운영 데이터 초기화**에서 `초기화`를 입력하는 기존 경로를 사용합니다. 이 경로는 먼저 `data/reset-backups`에 백업을 만듭니다. 물건을 남겨 둔 채 어느 초기화든 실행하면 그 물건이 기준 배경에 포함될 수 있습니다.

### 3-5. 발표 10분 전 최종 리허설

1. 파란색 볼펜 하나를 화면 중앙에 놓습니다.
2. 손과 몸을 화면에서 완전히 뺍니다.
3. 등록될 때까지 다른 물건을 움직이지 않습니다.
4. **보관 물품**에서 이름, `일반 물품`, `60일`, AI 제공자를 확인합니다.
5. 볼펜을 완전히 치우고 다시 화면 밖으로 나옵니다.
6. `회수됨`으로 바뀌는지 확인합니다.
7. 발표용 목록을 다시 비울 필요가 있다면, 물건이 없는 상태에서 3-4의 초기화를 반복합니다.
8. 빈 화면을 다시 기준으로 잡고 **변화를 기다리는 중**에서 멈춰 둡니다.

## 4. 실제 발표에서 보여 줄 순서

1. **대시보드**에서 현재 보관 수량과 활동 기록을 설명합니다.
2. **카메라**로 이동해 실시간 영상과 **변화를 기다리는 중** 상태를 보여 줍니다.
3. 물건을 한 번에 하나만 촬영대 중앙에 놓습니다.
4. 손과 몸을 완전히 치우고 기다립니다.
5. 시스템이 움직임 종료, 장면 안정화, 변경 전·후 전체 화면과 변화 영역 비교, AI 분석을 수행한다고 설명합니다.
6. 새 물품이 나타나면 이름, 설명, 분류와 자동 보관 기한을 보여 줍니다.
7. 같은 물건을 완전히 치우고 화면 밖으로 나옵니다.
8. 기존 위치의 물체가 사라진 것을 확인해 `회수됨`으로 바뀌는 모습을 보여 줍니다.

안정화 3초와 네트워크 API 호출이 있으므로 결과까지 보통 수 초에서 수십 초가 걸릴 수 있습니다. 기다리는 동안 물건을 다시 만지거나 두 번째 물건을 놓지 않습니다.

### 실물 분류와 관리 기능을 함께 검증하기

시연에 사용할 귀중품·일반 물품·식품을 각각 실제 카메라에 놓아 추가·이동·제거를 미리 검증합니다. 이름과 분류, 90일·60일·1일 기본 보관 기한을 확인하고, 정보 편집·만료·알림·기한 연장·폐기·복원까지 실제 운영 흐름을 끝까지 점검합니다. **시연 도구**의 사전 정의 물품 버튼은 관리 화면을 연습하는 모사 기능이며, 실제 카메라 감지와 API 분석 검증을 대신하지 않습니다.

## 5. 문제가 생겼을 때 순서대로 확인

### 5-1. 관리자 주소가 안 열림

먼저 화면과 명령을 복잡하게 건드리지 말고 다음 순서만 확인합니다.

1. Android의 핫스팟이 켜져 있습니까?
2. **연결된 기기**에 `refound-pi`가 있습니까?
3. Android에서 모바일 인터넷이 실제로 됩니까?
4. 노트북 Tailscale이 `Connected`입니까?
5. 노트북을 학교 Wi-Fi에서 `ReFoundPhone`으로 바꿔도 안 열립니까?

그래도 안 열리면 노트북이 같은 핫스팟에 연결된 상태에서 PowerShell로 접속합니다.

```powershell
ssh refound@refound-pi.local
```

Pi 터미널에서 다음을 한 줄씩 실행합니다.

```bash
tailscale status
sudo tailscale serve status
sudo systemctl status refound.service --no-pager
curl --fail http://127.0.0.1:8000/api/health
```

정상 기준은 다음과 같습니다.

- Tailscale에 Pi와 노트북 장치가 보입니다.
- Serve 상태에 현재 `https://...ts.net` 주소와 `http://127.0.0.1:8000` 프록시가 보입니다.
- 서비스가 `active (running)`입니다.
- health 요청이 JSON을 반환합니다.

서비스만 비정상이면 다음을 실행하고 20초 뒤 다시 확인합니다.

```bash
sudo systemctl restart refound.service
sudo journalctl -u refound.service -n 100 --no-pager
```

#### Tailscale만 안 될 때 쓰는 안전한 비상 접속

Android 연결 기기에 Pi가 보이고 로컬 SSH도 되지만 Tailscale 주소만 열리지 않는다면, 앱의 공개 범위를 넓히지 않고 SSH 터널로 접속할 수 있습니다. **Windows PowerShell**에서 실행합니다.

```powershell
ssh -L 8000:127.0.0.1:8000 refound@refound-pi.local
```

로그인된 PowerShell 창을 닫지 않은 상태로 브라우저에서 다음 주소를 엽니다.

```text
http://127.0.0.1:8000
```

`.local`이 안 되면 Android 연결 기기 목록의 Pi IP를 SSH 명령 마지막에 사용합니다. 이 방법은 노트북과 Pi가 모두 `ReFoundPhone`에 연결됐을 때 사용할 수 있습니다.

### 5-2. 웹은 열리지만 라이브뷰가 안 나옴

1. 20초 정도 기다린 뒤 브라우저를 한 번 새로 고칩니다.
2. 다른 카메라 검사 프로그램을 실행하지 않습니다. 카메라는 한 프로그램만 사용할 수 있습니다.
3. Pi에서 서비스 상태와 로그를 확인합니다.

```bash
sudo systemctl status refound.service --no-pager
sudo journalctl -u refound.service -n 100 --no-pager
```

### 5-3. 화면이 계속 움직였다고 감지함

1. 카메라와 리본 케이블, 받침대를 단단히 고정합니다.
2. 깜박이는 조명, 창문 그림자와 자동 밝기 변화가 적은 위치로 옮깁니다.
3. 화면이 안정된 뒤 기준 화면을 다시 잡습니다.
4. 픽셀 변화 민감도는 먼저 현재 검증된 값으로 두고 발표 직전에 크게 바꾸지 않습니다.
5. 민감도를 바꿔야 한다면 한 단계씩 바꾸고 등록과 회수를 모두 다시 시험합니다.

### 5-4. 물건은 저장되지만 이름이 `확인 필요한 새 물품`임

이 상태는 감지 자료를 잃어버린 것이 아닙니다. API 오류, 낮은 확신도 또는 불확실한 추가·제거 판단 때문에 관리자 검토 대상으로 보존한 것입니다.

1. Android 모바일 인터넷을 확인합니다.
2. 관리자 웹의 AI 제공자 표시를 확인합니다.
3. 같은 물건을 반복해서 놓아 중복 기록을 만들지 않습니다.
4. Pi 로그를 확인합니다.

```bash
sudo journalctl -u refound.service -n 100 --no-pager
```

### 5-5. 최후의 발표용 대체 수단

인터넷이나 AI만 실패하고 웹과 카메라가 열리면, 실제 로컬 감지·저장 구조를 설명하고 **시연 도구**의 사전 정의 물품으로 관리 화면과 1일·60일·90일 정책을 보여 줍니다.

Pi 자체의 `ReFound-Demo` 오프라인 Wi-Fi는 집에서 미리 생성과 복귀를 모두 시험한 경우에만 사용합니다. 이 모드에서는 `http://10.42.0.1:8000`으로 웹과 로컬 기능을 사용할 수 있지만 인터넷이 없으므로 OpenAI, Gemini와 이메일은 작동하지 않습니다. 발표 당일 처음 설정하지 마세요. 설정과 복귀 방법은 [Raspberry Pi 전체 가이드의 9장](RASPBERRY_PI_GUIDE.md#9-인터넷이-없을-때-pi-자체-핫스팟-사용하기)에 있습니다.

핫스팟을 미리 저장하지 못했더라도 micro-HDMI 모니터와 USB 키보드가 있으면 현장에서 직접 연결할 수 있습니다. 케이블 연결부터 로그인, 두 종류의 비밀번호와 `nmcli` 명령까지 [모니터·키보드 현장 Wi-Fi 연결 가이드](PI_MONITOR_WIFI_GUIDE.md)에 정리되어 있습니다.

## 6. OpenAI 키를 나중에 교체하는 법

API 키는 웹 화면이 아니라 Pi의 `/opt/refound/.env`에 보관합니다. 키를 채팅, 발표 자료, Git 또는 화면 캡처에 넣지 않습니다.

`.env`에는 인증 키만 둡니다. 어떤 제공자와 모델을 쓸지는 관리자 웹의 **설정 → AI 분석**에서 선택하며 SQLite 설정에 저장됩니다. `provider=...`나 모델명을 `.env`에 추가할 필요가 없습니다.

새 물건을 놓거나 움직이지 말고, 등록된 물품의 **분석 중** 표시가 사라진 뒤 변경합니다. **변화를 기다리는 중**은 카메라 장면이 안정됐다는 뜻이며, 별도로 실행되는 AI 작업까지 끝났다는 뜻은 아닙니다. 모호한 회수의 AI 재검증이 진행 중이라면 결과나 관리자 확인 표시까지 기다립니다.

서비스 재시작은 이미 접수한 AI 작업을 마칠 때까지 기다리므로 즉시 끝나지 않을 수 있습니다. 기본 Pi 설정의 종료 대기 한도는 5분입니다. 재시작 명령이 끝나기 전에 전원을 끄거나 명령을 반복하지 않습니다. 강제 종료된 분석은 다음 시작 때 사진과 기록을 보존한 **확인 필요** 상태로 남으며 자동으로 다시 호출하지 않습니다.

1. [OpenAI API 키 페이지](https://platform.openai.com/api-keys)에서 새 키를 만듭니다.
2. 필요한 결제 수단, 크레딧과 사용 한도를 확인합니다.
3. Pi에 SSH로 접속합니다.
4. 다음 명령으로 파일을 엽니다.

```bash
nano /opt/refound/.env
```

기존 줄의 값만 새 키로 바꿉니다.

```dotenv
OPENAI_API_KEY=새_OpenAI_API_키
```

같은 변수 줄을 파일 아래에 하나 더 추가하지 마세요. 이 프로젝트는 먼저 나온 값을 사용하므로 위쪽의 빈 줄이 아래쪽 새 키를 가릴 수 있습니다. `export OPENAI_API_KEY=...` 형식이나 줄 끝 주석도 사용하지 않습니다.

Nano에서는 `Ctrl+O`, `Enter`, `Ctrl+X` 순서로 저장하고 닫습니다. 그다음 실행합니다.

```bash
chmod 600 /opt/refound/.env
sudo systemctl restart refound.service
```

관리자 웹에서 **설정 → AI 분석**으로 이동해 다음을 확인합니다.

- AI 제공자: `OpenAI` 또는 `자동 선택`
- 모델: `gpt-5.6-luna` 또는 [OpenAI 모델 목록](https://platform.openai.com/docs/models)의 이미지 입력 지원 모델 ID
- 메인 화면: `OpenAI · 모델명`, `키 설정됨`

`키 설정됨`은 키가 파일에 존재한다는 뜻이며 키가 유효하다는 검증은 아닙니다. 키 권한, 잔액과 모델 접근까지 실제로 검증하려면 **시연 물품 추가 버튼이 아니라 실제 카메라에 물건을 놓아** 새 분류를 한 번 성공시켜야 합니다.

새 키로 실제 분류가 성공한 것을 확인한 뒤 이전 키를 OpenAI 대시보드에서 폐기합니다. 키 유출이 의심되면 확인을 기다리지 말고 이전 키부터 즉시 폐기합니다.

## 7. Gemini API를 추가하거나 전환하는 법

이 프로젝트는 Gemini를 이미 지원하므로 Python 패키지나 코드를 추가할 필요가 없습니다.

### 7-1. Gemini 키 만들기

1. [Google AI Studio API 키 안내](https://ai.google.dev/gemini-api/docs/api-key)를 엽니다.
2. Google 계정으로 로그인합니다.
3. 새 API 키를 만듭니다.
4. 2026년 9월 기준으로 새로 발급되는 **Authorization/Auth key**를 사용합니다. 오래된 제한 없는 Standard key를 재사용하지 않습니다.
5. 필요한 할당량과 결제 설정을 확인합니다.

### 7-2. Pi에 Gemini 키 저장

Pi SSH 터미널에서 다음을 실행합니다.

```bash
nano /opt/refound/.env
```

`GEMINI_API_KEY` 줄에 새 키를 넣습니다. OpenAI도 계속 사용할 생각이면 기존 OpenAI 줄은 그대로 둡니다.

```dotenv
OPENAI_API_KEY=기존_OpenAI_키
GEMINI_API_KEY=새_Gemini_키
```

`GEMINI_API_KEY=` 줄이 이미 있으면 그 줄을 수정하고 같은 이름의 줄을 새로 추가하지 않습니다. 키 앞에 `export`를 붙이거나 줄 끝에 설명을 붙이지 않습니다.

저장한 뒤 권한을 다시 고정하고 서비스를 재시작합니다.

```bash
chmod 600 /opt/refound/.env
sudo systemctl restart refound.service
```

### 7-3. 웹에서 Gemini 선택

1. 관리자 웹에서 **설정 → AI 분석**을 엽니다.
2. AI 제공자를 `Google Gemini`로 바꿉니다.
3. 모델에 `gemini-3.5-flash-lite`를 입력합니다.
4. **변경사항 저장**을 누릅니다.
5. 메인 화면에 `Google Gemini · gemini-3.5-flash-lite`와 `키 설정됨`이 나오는지 확인합니다.
6. 빈 화면을 기준으로 잡고 실제 물건을 놓아 새 분류를 시험합니다.
7. 물품 상세의 **분석 제공자**가 Google Gemini인지 확인합니다.

모델 ID가 폐기되거나 바뀌면 [Gemini 공식 모델 목록](https://ai.google.dev/gemini-api/docs/models)에서 **이미지 입력을 지원하는 안정 버전의 정확한 모델 ID**를 확인해 웹 설정의 모델 값만 바꿉니다. 모델 값은 웹에서 저장 즉시 이후 분석에 적용되므로 `.env` 수정이나 서비스 재시작이 필요하지 않습니다.

### 7-4. `자동 선택`의 정확한 동작

두 키가 모두 있고 제공자를 `자동 선택`으로 두면 다음 순서로 작동합니다.

1. OpenAI를 먼저 호출합니다.
2. OpenAI 요청이 HTTP 오류, 시간 초과 또는 응답 해석 실패로 끝나면 Gemini를 호출합니다.
3. 둘 다 실패하면 감지 기록을 없애지 않고 관리자 확인 대상으로 저장합니다.

OpenAI가 정상 응답했지만 `uncertain` 또는 낮은 확신도를 반환한 경우에는 Gemini에 재질문하지 않습니다. 자동 선택은 **API 장애 대비용 폴백**이지 두 모델의 다수결 기능은 아닙니다.

두 API가 모두 시간 초과되면 자동 선택은 결과가 나오기까지 약 60초 또는 큐 대기를 포함해 더 오래 걸릴 수 있습니다. 발표 때는 새 카드에서 실물 테스트에 성공한 제공자 하나로 고정하고, 자동 선택은 두 제공자를 각각 검증한 뒤 사용합니다. 이전 카드의 OpenAI 성공 기록만으로 새 설치의 키·네트워크 정상 여부를 판단하지 않습니다.

| 원하는 운영 방식 | `.env` | 웹의 AI 제공자 |
|---|---|---|
| 지금처럼 OpenAI만 사용 | OpenAI 키만 설정 | OpenAI 또는 자동 선택 |
| Gemini만 사용 | Gemini 키만 설정 | Google Gemini |
| OpenAI 장애 때 Gemini 사용 | 두 키 모두 설정 | 자동 선택 |
| 인터넷 없는 로컬 기록 | 키는 무관 | 오프라인 분석 |

제공자를 OpenAI 또는 Gemini로 직접 고정하면 다른 제공자로 자동 전환하지 않습니다. 선택한 키가 없거나 호출이 실패하면 로컬 관리자 확인 상태로 남습니다.

## 8. API 변경 후 검증표

- [ ] `.env`의 변수 이름을 `OPENAI_API_KEY` 또는 `GEMINI_API_KEY`로 정확히 썼습니다.
- [ ] `.env`를 저장한 뒤 `chmod 600`을 실행했습니다.
- [ ] 키를 바꾼 뒤 `refound.service`를 재시작했습니다.
- [ ] 웹 설정에서 원하는 제공자와 정확한 모델 ID를 저장했습니다.
- [ ] 메인 화면에서 활성 제공자와 모델을 확인했습니다.
- [ ] **실제 카메라 물건**으로 한 번 분류했습니다.
- [ ] 물품 상세에서 분석 제공자가 맞는지 확인했습니다.
- [ ] 실패했다면 키를 출력하지 않고 서비스 로그만 확인했습니다.

```bash
sudo journalctl -u refound.service -n 100 --no-pager
```

기존 물품은 API를 바꿔도 삭제되거나 다시 분류되지 않습니다. 전환 후 새로 감지한 물품부터 새 제공자를 사용하며, 기존 기록에는 당시 사용한 제공자가 그대로 남습니다.

로그에서 다음 상태 코드가 보이면 원인은 대체로 다음과 같습니다.

| 오류 | 먼저 확인할 것 |
|---|---|
| `401` | 키 오타, 폐기되거나 만료된 키 |
| `403` | 프로젝트 또는 API 사용 권한 |
| `404`, `model not found` | 모델 ID 오타 또는 해당 계정의 모델 접근 권한 |
| `429` | 사용량 한도, 잔액, 결제 또는 호출 속도 제한 |
| timeout | Android 인터넷, 신호 세기 또는 제공자 연결 상태 |

웹의 모델 입력란은 저장할 때 모델 존재 여부를 원격으로 검사하지 않습니다. 오타는 다음 실제 감지에서 발견되므로 모델을 바꾼 뒤에는 반드시 실물 분류를 한 번 실행합니다.

## 9. 발표 종료 후

1. 촬영 구역의 물건을 치웁니다.
2. 필요한 결과 화면과 발표 자료만 저장합니다. API 키가 보이는 화면은 촬영하지 않습니다.
3. Pi에 SSH로 접속할 수 있으면 안전하게 종료합니다.

```bash
sudo shutdown -h now
```

4. 30초 정도 기다리고 ACT LED가 멈춘 뒤 전원을 뽑습니다.
5. Android 핫스팟과 모바일 데이터를 끕니다.
6. API 제공자 대시보드에서 당일 사용량과 예상하지 못한 호출이 없는지 확인합니다.
