# 성능 수치를 채우는 순서

성능 수치는 원고에서 예상하여 쓰는 것이 아니라, 실제 행동과 시스템 기록을 비교해서 계산한다. 지금의 297개 입력 항목은 실험 297번을 뜻하지 않는다. 장비 정보, 여러 표의 통계, 실패 기록 등을 나눈 칸이며 상당수는 같은 원시 기록에서 자동 집계한다.

## 역할 분담

- 사용자: Pi를 실제 장소에 설치하고, 정해진 순서로 물품을 놓고·옮기고·치우는 실험을 진행한다. 실제 카메라와 설치·냉각·전원 정보를 확인한다.
- 코드 작업: 사건·DB·VLM의 시각, 호출과 실패를 자동 저장하는 계측 및 비교 실행기를 준비한다. 현재 저장소에는 일부 코어 실험 도구가 있으나 종단간 계측과 공통 비교 실행기는 추가 작업이 필요하다.
- 분석 작업: 촬영 자료에 실제 일어난 일인 정답을 표시하고, 기록과 비교하여 CSV·성능표를 만든다. 표가 확정된 뒤 초록·논의·결론을 결과에 맞춰 수정한다.

## 무엇을 어떻게 측정하는가

| 알고 싶은 것 | 실제로 하는 일 | 원고의 위치 |
|---|---|---|
| 추가·이동·제거를 잘 구분하는가 | 각 행동을 촬영하고 정답 종류·위치·기존 물품 ID를 기록. 시스템 출력과 비교 | 표 7, 사건별 precision·recall·F1 및 이동 ID |
| 아무 일도 없는데 잘못 등록하는가 | 물품 상태를 바꾸지 않고 연속 감시. 조명·그림자 조건과 잘못 나온 사건을 기록 | 표 7·9, none 오작동률과 시간당 오탐 |
| 얼마나 기다려야 등록되는가 | 실제 행동 종료, 로컬 사건, 임시 DB 저장, 최종 결과의 시각을 기록 | 표 10, 지연의 중앙값과 p95 |
| Pi에 얼마나 부담이 되는가 | 실제 Pi에서 서비스 실행 중 CPU·RAM·온도·실제 감시 FPS를 기록 | 표 10 |
| 보정 기능이 도움이 되는가 | 같은 안정 전후 이미지에 정합·조명·경계 억제 구성을 달리 적용 | 표 8·9. 코어 성능만 평가 |
| 다른 단순 구성보다 나은가 | 같은 연속 영상을 순수 차영상·상태기계 없는 구성·MOG2·전체 구성에 입력 | 표 7(b). 공통 사건 변환 규칙을 먼저 고정 |
| 외부 AI를 얼마나 호출하며 잘 판단하는가 | 같은 사건의 1장/전후 crop/전후 전체 장면/4장 입력을 비교. 실제 요청·응답·usage·전송량 기록 | 표 11 및 6-4절 |
| AI가 실패해도 기록을 보존하는가 | timeout·잘못된 JSON·대기열 포화 등을 통제하여 주입 | 표 13 |

Precision은 시스템이 있다고 보고한 사건 중 실제로 맞은 비율이고, recall은 실제 사건 중 시스템이 찾아낸 비율이다. F1은 둘을 함께 보는 값이다. 사건 종류뿐 아니라 위치가 맞는지도 함께 채점한다. p95는 측정된 지연의 약 95%가 그 값 이하라는 뜻이다. 실패하거나 놓친 사건이 지연 통계에서 빠질 수 있으므로 지연만 보여주지 않고 검출률도 함께 제시한다.

## 첫 실험은 작게 시작

먼저 약 40건의 파일럿을 계획할 수 있다. 예를 들어 추가·이동·제거·물품 변화 없음 각 10건으로, 소수의 다양한 물품과 조명·그림자 조건을 사용한다. 이는 촬영·기록·라벨링이 제대로 되는지 확인하고 설정을 조정하는 개발 실험이다. 이 숫자가 논문 심사를 위한 충분한 표본 수라는 뜻은 아니다. 본 실험의 표본 수는 파일럿에서 관찰한 사건 빈도·오류·불확실성과 촬영 세션 구성을 보고 정한다.

1. 장비와 설치 정보를 적고 프로그램 설정을 저장한다.
2. 자동 기록이 정상인지 짧은 동작으로 확인한다.
3. 정해진 행동을 수행하며 영상을 촬영한다. 손이 물품에서 떨어지고 최종 배치에 머무는 시점을 정답 행동 종료로 표시한다.
4. 영상으로 실제 사건 종류와 bbox, 이동 전·후의 ID를 라벨링한다. 시스템 출력이 정답을 대신하게 하지 않는다.
5. 파일럿으로 설정과 비교 실행 규칙을 고정한다. 그 후 다른 물리적 물품과 촬영 세션을 사용해 최종 평가 자료를 수집한다.
6. 원장과 CSV를 집계하여 결과 입력표를 채운다. 개선되지 않은 항목도 그대로 보고한다.

none의 짧은 파일럿 장면과 별도로, 시간당 오탐 측정에는 실제 연속 감시 시간이 필요하다. 전후 이미지 두 장만으로 시간당 오탐이나 종단간 지연을 계산하지 않는다. 모호 제거 의뢰를 로컬 제거 성공으로 바로 세지 않는다.

## 원고에 넣을 때

장비 모델·OS·카메라·냉각처럼 사실 확인으로 채울 항목부터 입력한다. 측정값은 원본 CSV, 실행 ID와 설정을 함께 보관한 뒤 [실측값 입력표](RESULTS_FILL_SHEET.md)의 대응 칸에 넣는다. 값이 없으면 빈칸 또는 미측정을 유지한다. 기본 목표 7 FPS는 측정 결과가 아니며, 전력계가 없으면 소비전력은 측정하지 않은 것으로 남긴다.

정확한 라벨, 분모, 자료 구분과 통계 규칙은 [실험 실행 지침](EXPERIMENT_GUIDE.md)을 따른다. 지금 시작할 기술 작업은 종단간 자동 계측 추가이며, 그 후 파일럿을 진행한다.
