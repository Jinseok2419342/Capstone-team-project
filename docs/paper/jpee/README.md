# 실천공학교육논문지(JPEE) 투고용 원고

[논문 작업공간](../README.md) · [제출용 워드 파일](../REFOUND_JPEE_MANUSCRIPT.docx) · [미리보기 PDF](REFOUND_JPEE_PREVIEW.pdf) · [원고](PAPER_DRAFT_JPEE.md)

2026-11-11에 만든 **두 번째 투고처용 원고**다. 연구와 숫자는 [JDCS 원고](../PAPER_DRAFT_JDCS.md)와 같다. **같은 연구이므로 두 학술지 중 한 곳에만 투고한다**(두 곳에 동시에 내면 중복 투고로 둘 다 탈락한다). 한 곳에서 게재 불가가 나온 뒤에 다른 곳에 내는 것은 괜찮다.

## 1. 두 학술지 비교 (2026-11-11 각 학회 홈페이지 확인)

| 항목 | 디지털콘텐츠학회논문지(JDCS) | 실천공학교육논문지(JPEE) |
|---|---|---|
| 제출 파일 | **HWP만**(학회 양식 2단). 직접 옮겨야 함 | **워드 또는 HWP**(1단). 워드 파일이 이미 만들어져 있음 |
| 심사료 | 6만 원(선불) | **0원** |
| 게재료 | 10쪽까지 30만 원, 초과 쪽당 5만 원 | 6쪽까지 20만 원, 초과 쪽당 3만 원 |
| 이 논문 예상 비용 | 약 36만 원(10쪽) | 약 26–29만 원(편집 후 8–9쪽으로 추정) |
| 사사 표기 | +10만 원 | +10만 원 |
| 회원 | 저자 1명 이상 정회원(연회비 5만 원, 9월 조사) | 회원 가입 필요(회비는 가입 화면에서 확인, 미확인) |
| 발행 | 매월 말 | 2·4·6·8·10·12월 말(연 6회) |
| 심사 | 심사위원 3명 | 심사위원 2명, 1차 심사 21일 이내(주말·공휴일 제외) |
| 추가 서류 | 논문투고 신청서 | **KCI 논문 유사도 검사 결과**, 저작권 활용 동의서 |
| 최종 조판 | 저자가 양식대로 직접 | 출판사가 다시 편집 |
| 범위 | 영상처리·IoT·지능정보 시스템(기술 논문) | 실천공학교육, 교육용 장비·시스템, 캡스톤 디자인, 학제 간 융합 |
| 분야 적합성 | 높음 | 캡스톤 개발 사례로 서술. 최근 Raspberry Pi·IoT 시스템 논문 게재 실적 있음(17권 5호, 18권 1·3호). 편집위원장이 범위가 맞지 않다고 보면 심사 전에 반려할 수 있음 |

JPEE 예상 쪽수는 추정이다. 게재료는 출판사가 편집한 뒤의 쪽수로 정해진다. JPEE 쪽이 비용이 적고 제출 파일을 바로 쓸 수 있지만, 어디에 낼지는 지도교수님과 정한다.

## 2. JDCS 원고와 다른 점

숫자·표의 값·실험 내용은 같다. 바꾼 것은 다음과 같다.

| 항목 | JDCS 원고 | JPEE 원고 |
|---|---|---|
| 제목 | …사건 기반 장면 변화 감지와 선택적 멀티모달 추론을 이용한 분실물 관리 시스템 | 저사양 엣지 장치와 시각언어모델을 이용한 사건 기반 분실물 관리 시스템의 설계와 구현 |
| 관점 | 영상처리·선택적 추론 시스템 | 학부 캡스톤디자인 개발 사례(설계 변경 과정과 근거 포함) |
| 새로 넣은 것 | — | III-A ‘개발 과정과 설계 변경’과 표 1(초기 계획 → 최종 구현, 루트 `README.md`의 변경표 근거), II-C ‘Raspberry Pi 기반 시스템 개발 사례’(JPEE 게재 논문 3편 인용), VI-F ‘개발 과정의 시사점’ |
| 뺀 것 | — | 관련 연구 비교표, 응답 항목 표(본문으로), 알고리즘 1, 식 (1) RANSAC 정의(본문으로) |
| 장 번호 | Ⅰ. / 1-1 | I. / A. / 1) |
| 요약 | 영문 168단어(120–170) | 국문 500자, 영문 184단어(200 이내), Key Words 5개(영문, 알파벳순) |
| 참고문헌 | 18편, 제목 첫 글자 대문자 | 21편, 제목은 문장형, `vol.`·`no.`, 학술지명 기울임 |
| 그림·표 위치 | 본문 가까이(단 맨 위) | 참고문헌 뒤에 모음 |
| 그림 크기 | 폭 1200 px | 폭 2040 px(양식: 17 cm에서 300 dpi 이상) |

교육 효과를 측정한 자료는 없으므로 원고에도 “개발 사례에서 얻은 것이며 교육 효과를 측정한 결과는 아니다”라고 적었다. 설문이나 학습 성과를 만들어 넣지 않는다.

## 3. JPEE 규격 대조

기준 자료는 `template/`에 있다: 투고 규정(2025-03-01), 심사 규정(2025-09-01), 국문·영문 워드 양식.

| 항목 | 규격 | 원고 |
|---|---|---|
| 파일 | MS-Word 또는 HWP, 1단, 줄 간격 1.5, 휴먼명조(영문 Times New Roman) 10 pt | 학회 국문 양식 파일을 열어 본문만 바꿔 만듦 |
| 순서 | 국문 제목, 영문 제목, (저자), 국문 요약, 영문 요약, 주제어, 본문, 참고문헌, 그림과 표 | 맞음. 심사용이라 저자·저자 소개 없음 |
| 요약 | 국문 500자, 영문 200단어 이내 | 500자, 184단어 |
| 주제어 | 규정은 5개 이상, 양식은 영문 5개 이내·알파벳순 | 영문 5개, 알파벳순 |
| 언어 | 국문 논문도 초록·표·그림 캡션·참고문헌은 영문 | 영문 요약, 영문 표, 캡션은 국문 줄 아래 영문 줄, 참고문헌 영문 |
| 장·절 번호 | I, II … / A, B … / 1) / a) | 맞음 |
| 수식 | 수식 편집기 | 워드 수식 개체, 번호 (1) |
| 참고문헌 | 10편 이상, 영문, 인용 순, 본문에 모두 인용 | 21편, 인용 순 1–21 |
| 그림·표 | 참고문헌 뒤, 캡션 국문 위·영문 아래, 그림 영문 캡션 끝에 마침표, 표는 워드 표 | 맞음 |
| 익명 | 심사용에는 저자 이름·소개 생략 | 맞음(파일 속성의 작성자도 비움) |

확인하지 못한 것: 규정은 국문 주제어도 적으라고 하지만 양식에는 영문 Key Words만 있다. 양식을 따랐고, 학회가 요구하면 국문 주제어 한 줄을 넣는다. 참고문헌 [3]의 학술대회 개최 장소는 JDCS 원고와 같이 비어 있다.

## 4. 투고 순서 (처음 하는 사람용)

1. **교수님과 정하기.** 어느 학술지에 낼지, 저자 순서·소속·교신저자를 정한다. 교수님께 보낼 메시지 초안은 [개정 상태 4절](../REVISION_STATUS.md)에 있다.
2. **워드 파일 열어 보기.** [`REFOUND_JPEE_MANUSCRIPT.docx`](../REFOUND_JPEE_MANUSCRIPT.docx)를 워드나 한글에서 열어 글자와 그림이 제대로 보이는지 본다. 휴먼명조 글꼴이 없으면 다른 명조체로 보이는데 문제없다(출판사가 다시 편집한다).
3. **회원 가입.** 학회 홈페이지 <https://kipee.or.kr> 에서 회원가입을 하고 안내되는 회비를 낸다.
4. **KCI 유사도 검사.** 한국학술지인용색인 <https://www.kci.go.kr> 에 로그인해 ‘논문유사도검사’에서 워드 파일을 올리고, 결과 확인서를 PDF로 저장한다.
5. **투고.** 학회 홈페이지 첫 화면의 ‘논문투고하기’로 들어가 안내 순서대로 입력한다. 올릴 것은 워드 파일, 유사도 검사 결과, 저작권 활용 동의서(투고 화면에서 양식 제공)다. 저자 정보는 투고 화면에 입력하고 원고 파일에는 넣지 않는다.
6. **심사 결과 받기.** 수정 요청이 오면 그 내용을 Claude에게 붙여 주면 원고를 고치고 답변서를 함께 쓴다.
7. **게재 확정 후.** 저자 이름·소속·저자 소개를 넣은 최종 파일을 내고 게재료를 낸다.

막히는 단계가 있으면 화면에 보이는 문구를 그대로 붙여 주면 된다.

## 5. 다시 만들기

```powershell
python docs\paper\manuscript\make_figures.py --width 2040 --out docs\paper\jpee\figures   # 그림 6장
python docs\paper\jpee\build_jpee_docx.py                                                   # 워드 파일
```

워드 파일은 `python-docx`로 만든다(`pip install python-docx`). 빌드는 국문 요약이 500자, 영문 요약이 200단어를 넘거나 주제어가 5개·알파벳순이 아니면 실패한다. 미리보기 PDF는 LibreOffice로 변환한 것이라 글꼴이 실제 워드 화면과 다르다.
