## 실측·투고 전에 남은 일

1. 실제 Pi의 OS, 카메라, 전원, 냉각과 설정을 기록한다. 종단간 timestamp, logical VLM job/HTTP attempt/usage, 각종 drop 원장을 추가한다.
2. privacy 부팅 동기화는 9월 18일 구현됐으므로 켠 상태의 실제 재부팅 복원을 확인한다. 논문용 공통 replay·장애 주입 runner를 준비하고, 20–50건 파일럿으로 촬영·라벨·baseline adapter·임계값을 고정한다.
3. 사건 검출과 오탐, Pi 지연·자원, VLM 증거 구성과 호출량, 비동기 장애 보존을 실제 자료로 평가한다. 자세한 분모와 통계는 [실험 지침](EXPERIMENT_GUIDE.md)을 따른다.
4. [실측 입력표](RESULTS_FILL_SHEET.md)를 원시 CSV로 채우고 결과가 지지하는 주장만 초록·논의·결론에 반영한다. 실제 성공·실패 영상과 그래프를 추가한다.
5. 저자·교신저자·소속을 확인한다. 현 [3]의 공식 영문 서지 또는 국문 표기 허용 여부를 확인하고, 심사용 식별정보를 제거한 최신 JDCS HWP 양식에 옮긴다.

## 확인 범위

- PDF 19쪽·4쪽과 PPTX 6장의 렌더링을 검사했다. 수식 분리와 기호 누락, 슬라이드 본문 잘림을 수정했다.
- PPTX 구조, 글꼴 지정, 6장 구성, 네이티브 표와 재가져오기 검증을 통과했다. PowerPoint 앱 자체에서 저장·재열기한 검증은 수행하지 않았다.
- 본문과 참고문헌 순서, 입력표 집합 일치 및 슬라이드 원문 발췌를 검사했다.
- 이번 작업은 원고·그림·발표 자료 작성이다. 애플리케이션 실행 코드는 수정하지 않았고, 새 현장 실험 또는 새 인식 성능 결과를 생성하지 않았다. 인계 문서의 136개 테스트 통과 기록은 과거 기록이며 이번 작업의 재실행 결과가 아니다.

## 재생성

`briefing/build_front_matter.py`는 전반부 PDF와 HTML을, `manuscript/build_manuscript.py`는 전체 PDF와 SVG를 만든다. `briefing/build_slides.mjs`는 Artifact Tool로 PPTX를 만들고 검사한다. PPTX 재생성 시에는 최종 파일과 검증 보고서에 새 경로를 지정한다.

`manuscript/revise_manuscript.py`는 보관된 초안을 기준으로 이번 개정을 재현하는 스크립트다. 이후 수동 편집이나 실측값 입력 뒤에는 실행하지 않는다. 당시 상태로 원고와 입력표를 다시 만들기 때문이다.
