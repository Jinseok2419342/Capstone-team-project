- **녹화 준비**: 노트북은 Windows 게임 바 녹화(Win+Alt+R, 브라우저 창이 앞에 있을 때)를 한 번 시험해 본다. 안 되면 캡처 도구의 ‘녹화’를 쓴다. 휴대폰 거치대가 있으면 보관대와 노트북 화면이 함께 보이게 둔다.
- **노트북 폴더 최신화**: 이번 변경이 `main`에 반영된 뒤 노트북 프로젝트 폴더에서 `git pull`(또는 GitHub에서 ZIP으로 다시 받기).
- (선택) **메일 확인까지 하려면** Pi의 관리자 설정에 관리자 메일·SMTP 계정, Pi `.env`에 `SMTP_PASSWORD`가 들어 있어야 한다. 비밀번호는 Pi에서 직접 넣고 채팅에 붙이지 않는다. 설정이 없으면 기능 점검에서 메일 항목만 ‘해당 없음’으로 남는다.

## 1. 켜기와 시작 (5분)

1. 평소 순서([START_HERE](../../START_HERE.md) 1–7단계)를 따르되, **Pi는 전원이 꺼진 상태에서 랜선 없이 켠다.** 핫스팟에 자동으로 붙고 웹 화면·영상이 나오면 그것이 남아 있던 ‘전원 재인가·무선 자동 연결’ 시험이다.
2. 노트북에서 **새 PowerShell**을 열고 프로젝트 폴더에서 실행한다.

   ```powershell
   python scripts\experiments\run_experiment.py
   ```

   Pi 이름으로 접속이 안 되는 날은 끝에 `--pi refound@192.168.137.xxx`처럼 현재 IP를 붙인다.

3. 물품 10개를 `텀블러/일반`처럼 한 줄씩 입력한다.
4. 장비 질문 6개에 답한다: microSD 용량, 냉각, 카메라 설치 높이·방향, 장소, 네트워크(Enter = 학교 Wi-Fi에 연결된 노트북 핫스팟), 오늘 꺼진 Pi를 랜선 없이 켰는지. 모르면 Enter. AI 모델 이름과 카메라 설정은 도우미가 Pi에서 자동으로 읽는다.

## 2. 시연 리허설 (5분) — 발표 시연의 백업 영상

1. 안내가 나오면 **노트북 화면 녹화(Win+Alt+R)**와 휴대폰 동영상을 켜고 Enter.
2. 첫 번째 물품으로 등록 → 이동 → 치우기를 한 번씩 한다. 매번 손을 뺀 뒤 Enter. 도우미가 `물품 ID 12 · 움직임이 끝나고 5.3초 뒤 기록`처럼 보여 주고 AI 이름이 나오면 알려 준다.
3. 등록 뒤 안내에 따라 **물품 상세 화면 캡처**(Win+Shift+S, AI 이름·분류·사진이 보이게).
4. 세 단계가 같은 물품 ID로 이어졌는지 도우미가 확인한다. 녹화를 끈다(Win+Alt+R).

리허설에서 결과가 계속 이상하면(등록이 안 됨, AI 결과가 안 옴) **Ctrl+C로 멈추고** 화면·조명·키를 확인한다. 본 실험 전에 문제를 찾는 시험 실행 역할도 한다. 리허설 결과는 결과표 1–3에 들어가지 않는다.

## 3. 실험 A — 등록·이동·제거 (60회)

1. 보관대를 비우고 관리자 화면의 **시연 초기화**를 누른 뒤 Enter. Pi 비밀번호를 물으면 입력한다(자원 기록 시작).
2. 화면에 `[3/100] 등록 · 텀블러 — 텀블러을(를) 빈자리에 놓고 손을 뺀 뒤 Enter`처럼 할 일이 나온다. 행동을 하고 **손을 뺀 뒤 Enter**를 누르면, 도우미가 시스템 반응을 기다렸다가 `→ 시스템 결과: 등록 · 맞음 · 5.2초`처럼 보여 주고 자동으로 기록한다. 10개 등록 → 10개 이동 → 10개 제거를 2회 반복한다.
3. 첫 10개 등록이 끝나면 **캡처 2장** 안내가 나온다: 대시보드(실시간 카메라 + 보관 물품), 보관 물품 목록(AI 이름·분류·사진). 최종보고의 실제 실행 화면과 논문 그림 2로 쓴다.

**결과가 다르면** 도우미가 무엇을 하면 되는지 알려 준다(예: “물품을 치웠다가 다시 놓아 주세요”, “잘못 생긴 카드는 감지 제외”). 상태를 맞춘 뒤 Enter를 누르면 다음으로 넘어간다. 이 정리 동작은 결과에 들어가지 않는다. 실수로 행동을 잘못했다면 Enter 대신 `s`를 눌러 건너뛴다.

## 4. AI 이름 확인 (3분)

실험 A가 끝나면 등록된 물품마다 `실제 '텀블러' → AI '스테인리스 텀블러' (일반). 이름 맞음? Enter=O`처럼 묻는다. 도우미가 먼저 추측해 두므로 맞으면 Enter, 다르면 `o` 또는 `x`를 누른다. 사람이 그 물건을 부를 만한 이름이면 O다. 분류(귀중품·일반·음식)는 처음 입력한 분류와 비교해 자동으로 채점한다.

## 5. 실험 B — 물품 변화 없음 (40회)

물품 1–5번을 올려 등록되면 Enter, 이어서 **휴대폰으로 실험 장면 사진 1장**(카메라·Pi·보관대 전체, 사람 얼굴 없이 — 논문 그림 5). 그다음 손을 넣었다 빼기 20회, 조명 끄고 10초 뒤 켜기 10회, 옆에 서서 그림자 드리우기 10회. 매번 행동이 끝나면 Enter. 정답은 모두 ‘반응 없음’이다.

## 6. 관리 기능 자동 점검 (3분)

Enter를 누르면 도우미가 보관 중인 물품 1개로 **정보 수정 → 검토 확정 → 기한 7일 연장 → 기한 경과(처리 필요) → 만료 알림 → 폐기 → 복원 → 수동 회수 → 복원 → 감지 제외 → 복원 → 원래 이름·기한으로 되돌리기 → 처리 이력 확인 → 테스트 메일**을 실제 Pi API로 차례로 실행하고 결과를 표로 남긴다. 물품은 마지막에 원래 상태로 돌아간다. 메일이 발송됐다면 메일함을 보고 `y`/`n`으로 답한다. 이어서 **활동 기록 화면 캡처 1장**.

## 7. 무인 1시간과 마무리

1. 안내가 나오면 Enter를 누르고 자리를 비운다. 사람이 화면에 들어오지 않게만 하면 된다. 이 1시간 동안 [최종보고 준비 안내](../presentation/FINAL_REPORT_PLAN.md) 5절의 프롬프트로 발표용 그림을 생성해 두면 시간을 아낄 수 있다(카메라에 비치지 않는 곳에서).
2. 1시간 뒤 도우미가 Pi 자원 기록을 끝내고 가져오려고 **비밀번호를 한 번 더** 묻는다.
3. `끝났습니다. 결과표: paper-run-…\paper-results\paper_tables.md`가 나오면 완료다. 같은 폴더의 `final_report_values.md`가 발표용 수치다.
4. 끝나면 평소대로 종료한다(Pi에서 `sudo shutdown -h now` → 초록 LED 점멸이 끝나면 전원 분리 → 핫스팟 끄기).
5. **Claude에게 줄 것**: `paper-run-…` 폴더 통째로(압축해도 됨), 캡처 3–4장, 실험 장면 사진 1장, 리허설 녹화 파일(발표 백업용, 용량이 크면 보관만).

**중간에 끊겼을 때**(노트북 절전, 터널 끊김 등): 터널을 다시 연 뒤 `python scripts\experiments\run_experiment.py --resume paper-run-…`로 실행하면 끝난 단계와 시도는 건너뛰고 이어서 진행한다. 시간이 부족하면 무인 감시를 `--idle-minutes 30`으로 줄일 수 있다(논문에는 실제 시간이 그대로 들어간다).

## 참고: 결과를 어떻게 계산하나

- **시스템 결과 판정**: Enter 후 관리자 화면의 활동 기록에 새로 생긴 카메라 사건으로 판정한다(새 물품 감지 → 등록, 이동 기록 → 이동, 회수 → 제거, 사라짐 확인 요청 → 확인 필요, 없음 → 반응 없음). 최소 6초, 사건이 없으면 18초(제거는 AI 재검증 때문에 30초)까지 기다린다.
- **정확도** = 맞은 시도 / 100(무변화는 ‘반응 없음’이 정답). Wilson 95% 신뢰구간을 함께 낸다.
- **정밀도·재현율·F1** = 표 5 혼동행렬에서 등록·이동·제거별로 계산. 무변화 시도에서 나온 사건은 그 사건의 오탐이다.
- **AI 호출 비율** = (등록 + 제거 검증) / 전체 감지 사건(무인 감시·리허설 제외), **AI 처리 시간** = 새 물품 감지 기록부터 분석 완료 기록까지.
- **움직임 종료 → 기록 시간** = Pi 카메라 상태의 마지막 움직임 시각부터 활동 기록 시각까지(둘 다 Pi 시계라 노트북 시계 차이와 무관). 맞게 판정된 시도만 쓴다. **→ AI 이름·분류 반영**은 여기에 AI 처리 시간을 더한 값이다. 1학기 목표 ‘감지~저장 10초 이내’를 채점하는 데 쓴다.
- **자원** = Pi 1초 간격 기록(CPU·메모리·온도)과 상태 API(분석 프레임률·처리 시간)의 평균·최대.
- **장면 사진**은 관리자 화면 미리보기(폭 800화소, 상태 표시 포함)에서 받은 것이다. 실패 원인 설명과 그림용이며, 정확도 계산에는 쓰지 않는다.
- 전력, 8시간 이상 안정성, 다른 방법과의 비교, 장애 주입은 이번 범위에서 뺐다. 심사에서 요청하면 그때 추가한다.
