## 0. 전날 준비

- **물품 10종**: 귀중품 3(예: 지갑, 이어폰 케이스, 시계), 일반 5(예: 우산, 텀블러, 필통, 책, 모자), 음식 2(예: 과자 봉지, 음료 캔). 너무 작거나(지우개) 바닥과 같은 색인 물건은 피한다. 기록지의 `물품1`–`물품10`을 실제 이름으로 바꾼다.
- **기록지**: [TRIAL_SHEET_TEMPLATE.csv](TRIAL_SHEET_TEMPLATE.csv)를 복사해 엑셀로 연다(100행이 미리 채워져 있음). 인쇄해서 손으로 적고 나중에 옮겨도 된다.
- **카메라 고정**: 실험 내내 카메라와 보관대(책상)가 움직이지 않게 테이프로 고정한다. 조명 실험 외에는 조명을 바꾸지 않는다.
- **장비 메모**(논문 표 4): 카메라 높이·거리(줄자), 방열판·팬·케이스 여부, microSD 용량, 실험 날짜·장소.

## 1. 시작 (10분)

1. 평소 순서([START_HERE](../../START_HERE.md)의 1–7단계)로 Pi를 켜고 노트북 브라우저에서 화면을 연다.
2. 보관대에서 물건을 모두 치우고 화면의 **시연 초기화**를 누른다. 이전 기록이 지워져 실험 기록만 남는다.
3. 설정 화면의 **AI 제공자·모델 이름**을 메모한다(논문 표 4).
4. **Pi에 로그인된 SSH 창**(터널 창)에서 자원 기록을 켠다. 창은 그대로 두고, 터널도 그대로 동작한다.

   ```bash
   mkdir -p /opt/refound/data/experiments
   /opt/refound/.venv/bin/python /opt/refound/scripts/experiments/monitor_pi_resources.py \
     --service refound.service --output /opt/refound/data/experiments/resources.csv \
     --disk-path /opt/refound/data --trial-id paper-1 --duration 14400
   ```

   `No such file` 오류가 나면 이 단계는 건너뛰고 나중에 알려 준다(CPU·온도 표만 빠짐).
5. 노트북에서 **새 PowerShell**을 열어 프로젝트 폴더로 이동한 뒤 처리 속도 기록을 켠다. Python만 있으면 되고 설치할 것은 없다.

   ```powershell
   python scripts\experiments\poll_health.py --output health.csv
   ```

## 2. 실험 A — 등록·이동·제거 (60회, 40분)

기록지 1–60행을 순서대로 진행한다.

1. **등록 1–10**: 물품을 하나씩 보관대에 놓고 손을 뺀다. 화면에 결과가 나오면(보통 10–20초) 기록하고 다음 물품을 놓는다. 물품은 서로 겹치지 않게 둔다.
2. **이동 11–20**: 놓인 물품을 하나씩 다른 빈자리로 옮긴다.
3. **제거 21–30**: 물품을 하나씩 치운다.
4. **2회차 31–60**: 같은 순서를 한 번 더 한다. 놓는 위치는 1회차와 조금 다르게 한다.

**‘결과’ 칸 적는 법** — 화면에 새로 나타난 것 하나를 적는다.

| 화면에 나타난 것 | 적을 값 |
|---|---|
| 새 물품 카드가 생김(‘확인 필요’ 표시가 붙어도) | 등록 |
| 기존 물품이 옮겨진 것으로 기록됨 | 이동 |
| 기존 물품이 회수 처리됨 | 제거 |
| 사라짐을 확정하지 못해 관리자 확인을 요청함 | 확인 필요 |
| 30초를 기다려도 아무 변화 없음 | 반응 없음 |

**등록 행에서 결과가 ‘등록’이면** AI 분석이 끝난 뒤 이름과 분류를 본다. 사람이 그 물건을 부를 만한 이름이면 `AI이름`에 O, 아니면 X. 분류(귀중품·일반·음식)가 맞으면 `AI분류`에 O, 아니면 X. 다른 행은 비워 둔다.

**틀렸을 때** — 결과를 그대로 적고, 다음 단계가 가능하도록 상태만 맞춘다.
- 등록이 안 됐으면: 그 물품을 치웠다가 다시 놓아 등록시킨다. 이 동작은 기록하지 않고 메모에 ‘재등록’이라고 적는다.
- 잘못 생긴 물품 카드(예: 이동이 새 등록으로 나온 경우)는 관리자 화면에서 **감지 제외**로 정리하고 메모에 적는다.
- 판정을 바꾸려고 같은 행동을 다시 시도하지 않는다. 실패도 결과다.

## 3. 실험 B — 물품 변화 없음 (40회, 20분)

시작 전에 물품 5개를 보관대에 올려 등록해 둔다(기록하지 않음). 이 상태에서 61–100행을 진행한다. 정답은 모두 ‘반응 없음’이다.

- **손 61–80**: 손을 보관대 위로 넣었다가 물건을 건드리지 않고 뺀다.
- **조명 81–90**: 실내 조명을 끄고 약 10초 뒤 다시 켠다(1회). 결과를 본 뒤 다음 회를 한다.
- **그림자 91–100**: 보관대 옆에 서서 5초 이상 그림자를 드리운 뒤 비켜선다.

## 4. 실험 C — 무인 1시간

물품 5개를 그대로 둔 채 **시작 시각과 종료 시각만 적고** 자리를 비운다. 그동안 사람이 화면에 들어오지 않게 한다. 잘못 생긴 사건은 집계 명령이 시각으로 자동으로 센다.

## 5. 마무리 (10분)

1. 노트북 PowerShell에서 `Ctrl+C`로 처리 속도 기록을 끝낸다.
2. Pi SSH 창에서 `Ctrl+C`로 자원 기록을 끝내고, 데이터베이스를 안전하게 복사한다(서비스를 멈출 필요 없음).

   ```bash
   /opt/refound/.venv/bin/python -c "import sqlite3; s=sqlite3.connect('/opt/refound/data/lost_items.db'); d=sqlite3.connect('/opt/refound/data/experiments/lost_items-copy.db'); s.backup(d); d.close()"
   ```

3. 노트북의 다른 PowerShell에서 파일을 가져온다(주소가 안 되면 평소처럼 `@` 뒤를 Pi IP로 바꾼다).

   ```powershell
   mkdir paper-run1
   scp "refound@refound-pi.local:/opt/refound/data/experiments/*" .\paper-run1\
   ```

4. **사진·화면 캡처**(논문 그림 2·5·6): 관리자 화면 캡처 1장, 실험 장면 사진 1장, 판정 성공 예 2장, 실패 예 1장(있다면). 사람 얼굴이 나오지 않게 한다.

## 6. 집계 (1분)

프로젝트 폴더의 PowerShell에서 실행한다. 시각은 실험 C에서 적은 값이다.

```powershell
python scripts\experiments\make_paper_tables.py --trials 기록지.csv `
  --db paper-run1\lost_items-copy.db --health health.csv --resources paper-run1\resources.csv `
  --idle-start 2026-10-20T15:00 --idle-end 2026-10-20T16:00
```

`paper-results\paper_tables.md`에 논문 표 5–8과 본문 숫자가 만들어진다. 기록지 값이 틀리면 몇 번째 행이 문제인지 알려 준다. 이 파일, 기록지, 사진을 Claude에게 주면 원고에 반영하고 결과에 맞게 요약·고찰·결론을 고친다.

## 참고: 결과를 어떻게 계산하나

- **정확도** = 맞은 시도 / 100. 무변화 시도는 ‘반응 없음’이어야 맞음. Wilson 95% 신뢰구간을 함께 낸다.
- **정밀도·재현율·F1** = 등록·이동·제거 각각에 대해 표 5 혼동행렬에서 계산. 무변화 시도에서 나온 등록·이동·제거는 그 사건의 오탐이다.
- **AI 호출 비율** = (등록 + 제거 검증) / 데이터베이스에 기록된 전체 감지 사건. 무인 감시 시간은 제외.
- **AI 처리 시간** = 활동 기록의 ‘새 물품 감지’ 시각부터 ‘분석 완료(또는 확인 필요)’ 시각까지. 기록 단위가 1초이므로 초 단위로 보고한다.
- **자원** = 1초 간격 기록의 평균·최대. 분석 프레임률과 프레임당 처리 시간은 시스템 상태 API 값이다.
- 전력, 장시간(8시간 이상) 안정성, 다른 방법과의 비교, 장애 주입은 이번 논문 범위에서 뺐다. 심사에서 요청하면 그때 추가한다. 기존 `experiments/`의 이미지 쌍 비교 도구는 그 경우에 다시 쓸 수 있다.
