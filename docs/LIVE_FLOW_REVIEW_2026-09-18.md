# 실제 운영 흐름 점검 — 2026-09-18

사용자의 최신 요구는 내장 예시 버튼을 통한 모의 시연이 아니라, 실제 카메라 감지와 관리 기능 전체가 자연스럽게 이어지는 것이다. 앞선 앱·영상·구조 개선 위에서 기능 사이의 연결과 일시적인 장애 복구를 점검했다.

이번 변경 전 소스는 `output/maintenance/2026-09-18-live-flow-review/source-before.zip`에 보존했다. 실제 운영 DB·촬영 사진·API 키와 논문·발표 산출물은 변경하지 않았다.

## 발견한 문제와 수정

| 문제 | 수정 후 동작 |
|---|---|
| MJPEG 연결 오류 후 주소가 남아 있어 자동 갱신이 다시 시작되지 않음 | 활성 화면에서 실패한 영상 연결을 재시도한다. 재시도 간격은 2→4→8→16→30초로 제한하며 실제 시점은 화면 갱신 주기를 따른다. |
| 물품 사진 로딩이 한 번 실패하면 이미지 요소가 삭제되어 같은 물품을 계속 표시할 때 복구되지 않음 | 이미지 요소와 편집 내용을 유지하며 사진만 다시 불러온다. 숨긴 화면·닫힌 상세창·서버 연결 실패 상태에서는 재시도를 미룬다. |
| 목록 조회 실패 화면이 분 단위 시간 갱신으로 오래된 목록에 덮임 | 새 목록 조회에 성공할 때까지 오류 상태를 유지한다. |
| 저장 성공 후 새 편집 화면이 보이는데 배경 목록 갱신이 끝나기 전 다음 저장·상태 변경 클릭이 무시됨 | 서버 변경이 완료되면 즉시 해당 작업 잠금을 해제한다. 이전 작업의 뒤늦은 정리가 다음 작업의 잠금을 해제하지 않도록 구분한다. |
| 다른 물품을 연 뒤 이전 저장의 충돌 응답이 도착하면 현재 편집 창에 잘못된 경고가 표시됨 | 충돌 응답이 속한 물품을 확인해 현재 다른 물품의 입력·편집 상태를 유지한다. |
| 390px 모바일 화면에서 필터의 숨김 라벨이 문서 폭을 423px로 늘려 메뉴·상세창이 화면 밖으로 밀림 | 필터 라벨을 위치 지정의 기준으로 만들어 숨김 요소가 가로 스크롤 영역을 벗어나지 않게 했다. 실제 visual viewport 기준으로 확인한다. |
| API 키 존재 여부만으로 ‘사용 가능’ 표시 | ‘키 설정됨’으로 표시한다. 실제 물품 분류 성공 여부는 별도로 확인해야 한다. |
| AI 응답 예산 450토큰에 추론 토큰도 포함되는데 기본 추론 설정 그대로 요청 | 응답 상한을 2048로 늘리고 기본 OpenAI 모델에만 `reasoning.effort=low`를 지정했다. 기본 모델명과 증거 이미지 4장은 유지한다. |
| JSON 형식 요청만 있고 출력 스키마·완료 상태 확인이 부족함 | OpenAI에는 strict JSON schema, Gemini에는 JSON schema를 요청한다. 완료되지 않은 응답·거절·안전 차단·토큰 제한 종료는 자동 판정에 사용하지 않는다. Gemini thought 부분도 결과에서 제외한다. |
| Gemini 3.x에 낮은 temperature를 강제로 지정 | sampling override를 제거하고 모델 기본값을 사용한다. |
| DB 읽기 실패에도 health가 항상 정상이라고 응답 | 실제 설정 읽기를 확인해 실패하면 `503`, `ok=false`, `database=unavailable`을 반환한다. 카메라 연결 여부는 별도로 표시한다. |
| Pi 재설치가 기존 접속 모드를 local로 덮어씀 | 기존 runtime 파일의 모드·주소·포트를 그대로 보존한다. |
| 이미 실행 중인 서비스를 재시작하지 않아 이전 버전 health로 설치 성공 처리 | 실제 재시작 후 새 MainPID와 저장된 접속 주소의 health를 확인한다. |
| 기본 systemd 종료 대기 20초가 비동기 AI 작업 처리보다 짧음 | 기본 Pi 큐를 고려해 종료 대기를 300초로 늘렸다. 사용자 지정 큐 크기나 장시간 장애의 무제한 완료를 보장하지 않는다. |

내장 예시 기능은 기존대로 제공하지만, 실제 감지·외부 AI를 호출한다는 잘못된 표현과 가짜 감지 표시를 없앴다. 학교 가이드는 카메라 대기와 AI 작업 완료를 구분하며, 배포 패키지에 학교·현장 Wi-Fi 가이드를 함께 넣는다.

API 오류에 포함된 키는 오류 문구를 자르기 전에 마스킹한다. 기존 순서에서는 자르는 경계에 걸친 키 일부가 로그에 남을 수 있었으며, 합성 키를 사용한 회귀 검사로 수정했다.

## 연결 검증 범위

전체 Python **264개**, Node **33개** 검사가 통과했다. Python·JavaScript 문법 검사도 통과했다. 아래 연속 검사는 이 전체 검사에 포함된다.

`tests/test_live_stream.py`는 실제 앱 lifespan, capture·dispatcher 스레드, 감지기와 안정 상태기계, 사건 callback, 임시 SQLite, 실제 executor와 HTTP API를 연결한다. 카메라 입력은 합성 프레임이고 VLM 응답은 모의 처리한다.

- 추가 → 임시 등록 → 분류 → 같은 ID 이동 → 제거 → 다시 놓았을 때 새 관찰 등록
- AI 응답 대기 중 이동·제거 → 늦은 응답이 현재 회수 상태·좌표·사진을 보존
- 물품 2개 추가 → 하나 이동·다른 하나 제거 → 남은 물품 제거, ID가 서로 바뀌지 않음

`tests/test_live_management.py`는 실제 API·SQLite·알림 스케줄러와 메일 작성기를 사용하고 SMTP 전송만 모의 처리해 편집·만료·알림·연장·폐기·복원·회수와 목록·통계의 일관성을 확인한다.

`tests/test_ai_transport.py`는 실제 HTTP 요청 직렬화와 모의 HTTP 응답으로 정상 JSON, 불완전 응답, 거절, 안전 차단, 잘못된 JSON, API 인증 실패와 timeout을 확인한다. 자동 모드에서만 다음 제공자로 넘어가고, 특정 제공자 고정 시 다른 제공자를 호출하지 않는 기존 정책을 유지한다. 실패한 관찰은 기존 ‘확인 필요’ 흐름에서 보존된다.

`tests/test_pi_deployment.py`는 가짜 systemctl/curl로 실제 셸 함수를 실행하고 임시 배포 패키지를 검사한다. 실제 Pi 서비스 재시작을 수행한 검증은 아니다.

## 실제 브라우저 검사

별도의 임시 프로필로 Chromium을 실행해 합성 카메라·모의 VLM/SMTP·임시 SQLite를 사용하는 로컬 서버에 접속했다. 데스크톱 12개, 모바일 4개 흐름을 확인했으며 처리되지 않은 JavaScript 예외는 없었다.

- 데스크톱: 대시보드·영상 표시, 48개 페이지 조회, 전체 DB 필터, 지연 분석 자동 반영, 편집 내용·409 충돌 보존, 재조회 후 저장, 기한 변경·알림, 폐기·복원·연장·회수, 감지 제외·검토 완료, 개인정보 보호 전환, 기준 화면 요청, 오프라인 후 연결 복구
- 모바일: 390×844 화면의 목록·상세창, 터치로 상세 열기·편집 저장·메뉴 전환. 수정 후 상세창 범위는 x=9–381, y=12–832로 실제 화면 안에 들어온다.

브라우저 검사에서 연속 저장 누락과 모바일 가로 넘침을 발견해 수정했다. `browser-before-mutation-fix.*`와 `browser-before-mobile-css-fix.*`는 수정 전 실패 증거다. `browser-desktop-result.json`에는 데스크톱 12개 성공 뒤 이어진 수정 전 모바일 실패가 함께 남아 있으며, 수정 후 모바일 성공은 `browser-mobile-result.json`으로 별도 기록했다. 최종 결합 결과는 `browser-validation-summary.json`을 따른다. 화면 캡처는 같은 폴더의 `browser-*.png`다.

## 요청 설정의 공식 근거

- OpenAI 기본 모델의 low 추론 설정 지원: [gpt-5.6-luna 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
- 응답 토큰 상한은 추론 토큰까지 포함하며 출력 전에 소진될 수 있음: [Reasoning 가이드](https://developers.openai.com/api/docs/guides/reasoning)
- Responses의 strict JSON schema 형식: [Structured Outputs 가이드](https://developers.openai.com/api/docs/guides/structured-outputs)
- Gemini의 JSON schema와 완료 사유: [GenerateContent API](https://ai.google.dev/api/generate-content)
- Gemini 3.x sampling 파라미터 권고: [Gemini 3.5 변경 안내](https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.5)

문서는 2026-09-18 확인했다. 기존 450토큰 설정의 실패 빈도나 수정 후 정확도·지연·비용은 실제 API로 측정하지 않았다. 스키마가 맞더라도 물품 판정의 정확성이 보장되지는 않는다.

## 남은 실기 확인

자동 검증 결과는 소프트웨어 연결과 회귀 검증이다. 실제 Pi 4 2GB, CSI/USB 카메라, 현장 조명과 손 가림, 실제 AI 계정·네트워크, SMTP 수신함의 동작은 현장 장비로 확인해야 한다. 실물 추가·이동·제거와 관리 생명주기를 함께 실행한 뒤 실제 성능 수치를 기록한다. 합성 결과를 논문 실험값으로 사용하지 않는다.

전체 검사 결과와 소스 해시는 같은 백업 폴더의 `FINAL_VALIDATION.json`에 기록한다.

최종 Pi 배포 파일은 `dist/refound-pi-2026-09-18-live-flow.tar.gz`다. 패키지의 43개 파일은 현재 소스와 바이트 단위로 일치하며 `.env`, 실제 데이터·사진, 캐시를 포함하지 않는다. 실제 Pi에는 이번 작업에서 설치하지 않았다.
